## 0. 公共约定（本插件特有的约束）

### 0.1 数据库迁移：本插件**目前没有任何迁移机制**

全库只有 `CREATE TABLE IF NOT EXISTS`（`src/audit.py` 顶部 `_SCHEMA_SQL` + `initialize()` 里 `conn.executescript(...)`，`src/audit.py:317`），**没有一处 `ALTER TABLE`**。因此给 `mod_events` 加列必须自带幂等迁移：

```python
async def _ensure_columns(self, conn, table: str, columns: dict[str, str]) -> None:
    """幂等补列：PRAGMA 查现有列，缺哪个补哪个（SQLite 支持 ADD COLUMN）。"""
    existing = {row[1] for row in conn.execute(f"PRAGMA table_info({table})")}
    for name, ddl in columns.items():
        if name not in existing:
            conn.execute(f"ALTER TABLE {table} ADD COLUMN {name} {ddl}")
```

接入位置：`AuditStore.initialize()` 建表之后调用；**失败只记 `logger.warning` 不阻塞启动**（沿用本插件"能力缺失→受限留痕→优雅降级"的既有约定）。

**新增列必须同步三处**，否则写入/查询会静默失效：

| 位置 | 作用 |
| --- | --- |
| `_SCHEMA_SQL`（新库） | 新装用户直接建全 |
| `_ensure_columns(...)`（老库） | 升级用户补列 |
| `WRITE_COLUMNS["events"]`（`src/audit.py:193` 附近） | `insert_event(**payload)` 的白名单，**不加就写不进去** |
| `LOG_TABLES["events"]`（`src/audit.py:169`） | 管理台日志筛选白名单（要按新列筛选时才需要） |

- **安全**：默认**只拒绝入群**，不自动移出已在群成员；每次增删写审计（`mod_actions` 或 `api_calls`）；
- **测试（5 例）**：审批链优先级（全局黑名单优先于信任邀请人）、幂等、权限校验、非法 openid 拒绝、解除后可通过；
- **工时**：1 天。

## 3. 设计合理性分析（B 部分）

### 3.1 逐项评估

| 功能 | 价值 | 成本 | 复杂度 | 触碰范围 | 回滚 |
| --- | --- | --- | --- | --- | --- |
| B3 域名白名单 | 中（消除跨插件误伤） | 低 | 低（纯函数 + 一处调用） | 规则层一处 + 配置 | 关开关即回到现状 |
| B1 申诉闭环 | 高（审核插件最大痛点） | 中 | 中（迁移 + 补偿 + 管理台） | audit/actions/commands/web_api/前端 | 保留旧指令语义；迁移只加列，可忽略新列回退 |
| B2 审核周报 | 中 | 低 | 低（聚合 SQL + 定时任务） | audit + main 任务 | 默认关 |
| B4 二维码 | 中 | 低 | 低（提示词 + 字段） | moderator/rules | 字段缺失即忽略 |
| B5 跨群黑名单 | 中 | 中 | 中（新表 + 审批链 + 管理台） | audit/join_review/web_api | 删表即回退 |

### 3.2 关键设计取舍

| 决策 | 取舍与理由 |
| --- | --- |
| 白名单**只降权**不豁免 | 豁免会让"发白名单域名 + 广告文案"成为绕过路径；降权后仍走规则与 LLM，安全边界不变 |
| 自学习白名单**默认关** | 误判样本少、且"通过即加白"可被社工利用；默认关 + 管理台可撤销 |
| 申诉补偿**不删原事件** | 审计完整性优先：保留原判 + 追加 `mod_actions`，便于事后复盘与规则优化 |
| 迁移**只加列不重建表** | SQLite `ALTER TABLE ADD COLUMN` 幂等且零风险；重建表需拷贝数据、风险高（本插件历史上用"独立新表"规避过主键问题，见 `progress_snapshot`） |
| 周报**纯文本** | 本插件 requirements 声明零第三方依赖，引入 Pillow/Chromium 只为一张周报不划算 |
| 二维码走**LLM 多模态** | 避免新增原生依赖；效果不足时再评估 `opencv/pyzbar`（须 import 失败优雅降级） |

### 3.3 明确不承诺

- 不保证申诉"自动判定"正确：自动补偿只做"解禁 + 加白（可选）"，**不自动改规则**；
- 全局黑名单不保证跨群一致（各群可自行 `黑名单`），也不自动移出已在群成员；
- 二维码识别依赖模型输出，**不保证 100% 解出**（失败即忽略，不阻断审核）。
