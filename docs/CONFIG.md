# 配置说明（面向用户）

配置入口：**AstrBot WebUI → 插件管理 → QQ群管理 → 管理台**。
配置保存在 AstrBot 插件 KV 中（`settings` / `groups` / `keywords` / `trusted` 等键），审计数据保存在
`data/plugin_data/astrbot_plugin_qq_group_manager/moderation.db`（SQLite）。

## 1. 总览页

| 项 | 说明 |
| --- | --- |
| dry-run | 默认**开启**：撤回/禁言/拉黑/移除只写审计日志不执行；**警告与上报仍会真实发送**（由 `dry_run_warn` 控制，默认开）。确认判定准确后再关闭。 |
| 默认模式 | `lenient`（宽松）为首次安装默认值：违规只警告。可选 `standard` / `strict` / `log_only`。 |
| 平台通道 | 显示是否已拿到 qq_official 的 botpy 客户端；不可用时无法调用任何 QQ 接口。 |
| 能力受限告警 | 近 24 小时的能力受限汇总（如 `err_code=11253` 需要白名单）。 |
| 后台任务 | `flush_state`（30s 落盘配置）、`probe_capabilities`（默认 1800s 重探能力）、`maintenance`（每小时检查/每日裁剪）。 |

## 2. 群管理页

- 群在收到消息后**自动登记**；也可手动填入 `group_openid` 添加。
- 「探测」会调用平台只读接口，刷新能力矩阵（绿=可用、红=受限、黄=无只读探测接口）。
- 「启用审核」会先校验：
  1. 平台通道可用；
  2. 能读取机器人群内状态（否则提示可能未获白名单授权）；
  3. `recv_msg_setting == all`（已开启「接收全部消息」）——未开启则**拒绝启用**并给出操作指引；
  4. 机器人不是群管理员时给出警告（此时违规消息只能警告，无法撤回/禁言）。
- 「停用审核」立即生效；「移除记录」只删除插件侧记录，不影响平台与群成员。

> 逃生舱：配置项 `allow_without_full_msg`（默认 `false`，不建议开启）可跳过第 3 步校验。

## 3. 日志中心

| Tab | 数据来源 | 写入时机 |
| --- | --- | --- |
| 审核事件 | `mod_events` | M2 接入后产生（每条被审核的消息一行）；支持按 `appealed`（是否申诉）筛选，列显示 `appeal_state` |
| 动作执行 | `mod_actions` | M2 接入后产生（撤回/禁言/警告/上报的结果） |
| API 调用 | `api_calls` | **现在就有**：每次 QQ 接口调用（含 err_code、耗时、重试次数、trace_id） |
| 能力受限 | `capability_log` | **现在就有**：能力探测失败或接口返回权限类错误 |

支持按群、关键字、时间范围筛选，分页浏览，导出 CSV/JSON，以及按类型清空（不可恢复）。

## 4. 工具页

- **能力自检**：一次性探测全部已登记群的能力，输出每项的 ✅/❌/➖、`err_code` 与建议。
- **审计库维护**：按保留策略裁剪、VACUUM 整理、备份下载。
- **实时事件（SSE）**：验证 WebUI ↔ 后端通道；M2 后审核事件会实时出现。
- **指令速查 / 配置摘要**。

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `enabled` | true | 插件总开关 |
| `dry_run` | true | 只记录不处置（撤回/禁言/拉黑/移除被拦截） |
| `dry_run_warn` | true | dry-run 期间是否仍发送警告与上报（关掉则完全静默，只写审计） |
| `mode` | lenient | 默认处置强度（strict / standard / lenient / log_only） |

| `sample_rate` | 1.0 | 送审比例 |
| `image_review` | off | 图片是否送审：off 不送 / with_text 仅图文混排送图 / always 纯图片也送 |

| `homoglyph_enabled` | true | 形近字表 |
| `template_enabled` | true | 广告模板规则 |
| `pinyin_enabled` | false | 同音匹配（需环境已安装 pypinyin） |
| `fuzzy_max_distance` | 1 | 模糊匹配编辑距离（0=关闭） |
| `auto_enforce_normalized` | false | 归一化/模板命中是否直接按规则动作处置（默认只送审） |

| `duplicate_flood_window` | 300 | 同文案多号刷屏的统计窗口（秒） |
| `duplicate_flood_members` | 3 | 同文案多号刷屏的人数阈值 |
| `llm_min_confidence` | 0.7 | 判定置信度门槛（M2） |
| `llm_qpm_per_group` | 20 | **单群每分钟 LLM 调用上限**（令牌窗口）：超出先等待，等待上限（15s）内仍满则跳过本次判定（内容审核降级为 review，入群审批转人工） |
| `llm_max_concurrency` | 4 | **全局同时在飞的 LLM 请求上限**（信号量），内容审核与入群审批共享 |
| `llm_context_messages` | 8 | 送审时附带最近 N 条群消息作为语境（0 = 关闭，退回"只看单条消息"） |
| `mute_steps` | 3→10 分钟 / 4→1 小时 / 5→1 天 | 按严重度禁言时长（M2） |
| `retention_events_days` | 30 | 审核事件/动作保留天数 |
| `retention_api_days` | 7 | API 调用日志保留天数 |
| `retention_capability_days` | 30 | 能力受限日志保留天数 |
| `retention_join_days` | 90 | 入群申请记录保留天数 |
| `db_path` | 空 | 自定义审计库路径（默认 `data/plugin_data/.../moderation.db`） |
| `store_text` | false | 是否在审计库保存消息正文（默认只存摘要 + 前 120 字） |


> **本地风险分权重**（0~100 累加后截断；达到 `risk>=N` 阈值即送审）：
> 精确命中硬规则 100 ／ 归一化或拼音命中 70 ／ 模板 45 ／ 联系方式 60 ／ 外链 25（命中 `domain_allowlist` 时不计）／ 8 位以上长数字串 60（6~7 位 20）／
> 引流词共现 25 ／ 同文案多号 35 ／ 刷屏 20 ／ 重复字符 15 ／ 超长 10 ／ 图片 60。
>
> `rule_hit` 只认"规则/模板命中"（不含内置启发式）：默认组合 `["rule_hit", "risk>=60"]` 下，
> **闲聊、偶尔发个链接都不送审**（链接仅 25 分），而变体广告、模板命中、联系方式、长号码、同文案多号刷屏都会送审。

## 6. 让处置真正生效（dry-run 切到实际处置）

插件有三层保护，命中规则却只看到警告时按这个顺序检查：

0. **群级模式覆盖**：群配置里的模式优先于全局默认。群首次登记时**不再**复制全局值（空 = 跟随全局），
   但历史群可能残留覆盖 —— 用 `审核状态` 查看会标注"（群级覆盖）"还是"（跟随全局）"，
   需要改就用 `审核模式 标准`（设本群）或 `审核模式 跟随`（清除覆盖），也可在管理台「群管理」表格里直接选。
1. **模式**：`lenient`（宽松，默认）只保留警告与上报；要让撤回/禁言生效请改为 `standard`
   （矩阵：sev3 警告+禁言、sev4 撤回+禁言、sev5 撤回+禁言+上报）或 `strict`。
2. **dry-run**：开启时撤回/禁言/拉黑/移除只写审计不执行（警告与上报仍会真实发送）。
3. **能力**：撤回与禁言要求机器人是该群管理员；非管理员时这两类动作会被跳过并在审计里记录原因。

操作方式（二选一）：

- 群内指令：`审核模式 标准` 加 `dry-run 关闭`（单独发送 `dry-run` 查看当前状态，`dry-run 开启` 随时回退）。
- 管理台：「策略」页把默认模式改为标准、取消勾选「dry-run」，保存。

### 6.2 变体与黑话识别能力（v0.4+）

| 能力 | 覆盖写法 |
| --- | --- |
| 全角/半角、大小写 | `ｊｉａ群` → jia群（NFKC 折叠） |
| 拉丁拼音/缩写 | `jia群` → 加群、`kouqun` → 扣群、`wx`/`vx` → 微信（按词边界折叠，不拆坏 `wxid_abc123`） |
| 插入符号/空格 | `加-群-领-资-料`、`资 源 合 集` |
| 形近字 | 珈→加、裙→群、苓→领、叩→扣、爿→片、浮→福、莉→利、撩→聊 |
| 拆字 | `君羊` → 群 |
| 繁体 | 機→机、發→发、車→车、資→资、領→领、進→进、號→号 … |
| 同音（需 pypinyin） | `jiaqun ling ziliao`、`看爿` → 看片 |
| 黑话/暗语 | 懂的都懂、你懂的、自取、上车、车牌、防失联、备用群、稳赚不赔、全网首发 … |
| 联系方式变体 | `V：abc123`、`裙号 123456`、weixin/vx/wxid_/tg、中文数字号码 |
| 扣群口语写法 | `叩群`/`抠群` → 扣群，并计入真实渠道（模板 `require_channel` 依赖它） |
| 软性开群话术 | 开群场景词 × 诱饵词 × 催促词（`新群开张，福利多多，手慢无`）→ 模板 `ad_open` |

> 命中上述任一形态只代表"**值得送审**"；是否违规仍由 LLM 判定，处置按判定到的类别与严重度执行。

- **图片**：默认**不送审**（避免无谓的 token 开销）。把 `image_review` 设为 `with_text`（图文混排时把图一起交给模型）
  或 `always`（纯图片也送），模型按多模态方式同时看文字与图片；单条最多送 `image_review_max` 张（1~4）。
- **语音**：平台会给出 `asr_refer_text`（语音转写），插件把它当正文一起送审。
- **视频/文件**：只记录类型，不送审（平台未提供转写）。
- 图片判定同样走提示词里的 JSON 契约与置信度门槛；需要模型具备视觉能力，否则图片会被忽略（可用「策略 → 试跑」验证）。

> 每次判定都会在「日志中心 → 审核事件」留痕（来源 rule/llm、分类、严重度、置信度、动作）；
> 若动作被模式或 dry-run 拦下，插件日志会输出「以下动作未执行：['recall']（模式=lenient，dry_run=True）」，
> 群内警告文案也会附带一句说明。

## 6. 审核链路（策略 / 关键词视图）

| 视图 | 内容 |
| --- | --- |
| 策略 → 规则增强 | 归一化/形近字/模板/拼音开关、模糊距离、风险分阈值、同文案多号刷屏参数 |
| 规则增强（视图） | 广告模板与形近字表维护 + **判定测试**（展示三视图、命中依据、风险分明细、是否送审） |
| 策略 → 运行参数 | dry-run、模式（strict/standard/lenient/log_only）、**审核模型**、图片审核、置信度门槛、**语境条数**、采样率、送审条件、超时、单群 QPM、全局并发、日预算、缓存、熔断阈值、最长禁言、重复违规累加、通知会话 |
| 策略 → 处置矩阵 | verdict=violation 时按 severity(1-5) 勾选动作：警告 / 撤回 / 禁言 / 上报 / 拉黑 / 移除；lenient 模式只保留警告与上报 |
| 策略 → 提示词 | 自定义 system 提示词与 user 模板（支持占位符，含 `{context}` / `{context_count}`），留空使用内置默认 |
| 策略 → 试跑 | 粘贴一段文本，完整走「规则 → LLM → 动作规划」但不执行任何动作 |
| 关键词 | 硬规则（命中即处置）/ 软规则（提升关注）两栏，支持正则、作用域（全局/单群）、启用开关、命中测试 |

## 6.3 申诉闭环与误判白名单（申诉视图）

- **提交申诉**：成员**回复被处置的消息**发送 `申诉 <理由>`。插件优先按 Reply 关联到那条消息对应的审核事件；
  取不到引用时才回退"该成员在本群最近一条被处置记录"（插件日志会打印 `申诉 Reply 关联失败 … 回退最近一条`）。
- **处理申诉**：群管回复申诉消息发送 `申诉通过 / 申诉驳回 [理由]`，或在管理台「申诉」视图按状态（待处理/已通过/已驳回）、
  群、时间范围筛选后点「通过 / 驳回」（可填备注）。
- **通过后的补偿**：若原事件产生过禁言，插件调用 `unmute_member`（op=del）解禁并同步本地禁言台账；
  追加 `mod_actions(action="appeal_accepted", event_id=...)` 留痕；**不删除、不改写原审核事件**，回执申诉人并通知管理员会话。
- **误判自学习白名单**：`appeal_auto_whitelist` 打开时，申诉通过会把原消息摘要写入 `appeal_whitelist`；
  后续**同内容**消息在规则求值后跳过 LLM 送审，但仍写审计（`verdict=allow / category=whitelisted`）。
  白名单条目在管理台「规则增强」页展示并可**撤销**；该开关默认关闭，避免被社工利用。
- **只降权/只跳过送审**：域名白名单只取消 link 分，误判白名单只跳过送审；两者都**不豁免规则命中与处置矩阵**。

## 7. 成员与入群（成员与禁言 / 入群审批视图）

- **禁言台账**：展示本地记录（成员、到期时间、来源、理由），支持单条/批量解禁与「与平台对账」。
- **黑名单**：平台黑名单（内邀接口）与本地黑名单分栏展示；平台不可用时自动落到本地（仅影响插件判定）。
- **成员查询**：优先查本地缓存（群消息里见过的成员），输入完整 openid 时调用平台成员接口。
- **移除成员**：调用平台的批量移除接口（内邀能力），执行前需二次确认。
- **入群审批**：待审列表（含头像、QQ 等级、账号年龄、验证消息、风险提示、机器建议）→ 通过/拒绝（可填理由、可同时拉黑）；「立即拉取申请」手动触发轮询；
  下方展示官方策略列表（启停 / 全量扫描 / 白名单维护）与冲突提示。

**能力差异（重要）**：

| 字段 | QQ 官方 | OneBot（NapCat） |
| --- | --- | --- |
| 昵称 | ✅ | ⚠️ 需 `get_stranger_info` 补齐 |
| 头像 | ❌ 无此字段 | ⚠️ 由 QQ 号拼 `q1.qlogo.cn` 直链 |
| QQ 等级 / 注册时间 / QID | ❌ 无此字段 | ✅（NapCat 扩展，换协议端可能缺失） |
| 平台风险提示 `risk_tips` | ✅ | ❌ |

- 官方通道与未知平台**不会发起任何画像请求**，「资料缺失策略」对其不生效（否则会把所有官方申请变成人工审批）。
- 门槛只在字段**确有值**时命中：协议端不返回等级/注册时间时，等级与年龄规则不会触发。
- 头像复核结论**只能把「拟放行」收紧为拒绝**，不会反向放行；模型不支持图片时自动降级为纯文本判定。

## 8. 常见问题

**Q：为什么群信息显示"平台未返回"？**
A：群信息与群状态接口目前**仅对白名单机器人开放**（`err_code=11253`），需要向 QQ 开放平台申请；不影响其它功能。

**Q：为什么无法启用审核？**
A：需要群管理员在手机 QQ 的机器人资料页开启「接收全部消息」。管理台会直接给出指引原文。

**Q：成员列表 / 黑名单提示失败？**
A：这 5 个接口官方标注"该能力正在内邀接入中"。插件会调用并记录失败原因（含 trace_id），界面显示"内邀未开放"。

**Q：日志数据存在哪里？会不会无限增长？**
A：`data/plugin_data/astrbot_plugin_qq_group_manager/moderation.db`，按上表的保留期每日自动裁剪，可在工具页手动裁剪/备份/清空。
