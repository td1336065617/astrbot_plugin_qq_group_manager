# 平台能力调研：QQ 官方机器人「群聊管理」 & AstrBot 对接方式

> 调研时间：2026-09　|　对象：QQ 机器人官方文档 api-v2、AstrBot 插件开发文档、AstrBot v4.27.3 源码、botpy 1.2.1 源码
> 用途：本文是 `docs/设计方案.md` 的事实依据；标注 **【实测】** 的结论来自本机源码核对。

---

## 1. 结论速览

1. QQ 官方已补齐整套「群聊管理」OpenAPI：群信息、机器人群内状态、入群申请列表/审批、入群自动审批策略（含白名单）、群禁言（成员级读写 + 群级只读）、群成员列表/详情、群成员批量移除、群黑名单，以及**群消息撤回**。
2. 权限三档：**仅白名单**（群信息、群状态）、**白名单 + 内邀**（群成员管理 5 个接口）、**需机器人为群管理员**（入群申请、审批、禁言）；入群自动审批策略 6 个接口文档未标门槛。
3. **可以撤回消息**：`DELETE /v2/groups/{gid}/messages/{message_id}`（10 QPS，2 分钟内，管理员可撤回普通成员消息，ID 取自消息事件 `d.id`）。
4. **官方没有**：主动退群、群公告、设置/取消管理员、转让群主、解散群、**修改全员禁言**（`global_rule` 只读）、群名片/加群链接、openid→QQ 号反查。
5. 群消息默认只有 @机器人 的才推送；审核全部消息需群管理员开启「接收全部消息」（`recv_msg_setting == "all"`）。
6. 消息事件里 `author.member_role` 可得（member/admin/owner）→ 可用于群内权限分级。
7. AstrBot 侧通道：`event.bot` 是 botpy `Client`；群管理接口必须自己用 `Route(...) + await event.bot.api._http.request(route, json=...)` 打（AstrBot 自己也是这么调群信息接口的）。**【实测】** botpy 1.2.1 的 `BotAPI` 只有 `post_group_message` / `post_group_file` / `post_c2c_message` / `post_c2c_file`，没有任何群管理方法。
8. **入群申请事件收不到**：`GROUP_JOIN_REQUEST` 属 intent `1<<24`，AstrBot 适配器只订阅 `1<<25`，且 `botClient` 未实现相关回调 → **必须轮询**。
9. LLM 复用官方 SDK：`pid = await context.get_current_chat_provider_id(umo)` → `await context.llm_generate(chat_provider_id=pid, prompt=..., system_prompt=..., contexts=[])`。
10. 审核 handler 命中只把事件标记为 `is_wake`，**不会**触发聊天 LLM（只有 `is_at_or_wake_command` 为真才调 LLM）。

## 2. 鉴权与调用规范

| 项 | 内容 |
| --- | --- |
| 统一地址 | `https://api.bot.qq.com`（变更记录 20260810 明确统一；旧 `api.sgroup.qq.com` 在现行文档中已无记载） |
| 取 token | `POST /app/getAppAccessToken`，body `{appId, clientSecret}`；有效期 7200s，剩余 <60s 时重新获取会返回新值 |
| 鉴权头 | `Authorization: QQBot {ACCESS_TOKEN}`；发消息类另带 `Content-Type: application/json; charset=utf-8` |
| 响应 | 成功直接返回业务数据；失败 `{"err_code":..., "message":..., "trace_id":...}`，**按 err_code 判定**；追踪头 `X-Tps-trace-ID` |
| HTTP 状态 | 200 成功 / 204 成功无包体 / 201·202 异步成功但带 error body / 401 / 404 / 405 / 429 / 500·504 |

**关键错误码**

| err_code | 含义 | 应对 |
| --- | --- | --- |
| 11252 / 11253 / 11254 | 权限检查失败 / **未获接口权限（白名单）** / 接口被封禁 | 11253 标记能力不可用并留痕，不重试；11252 最多重试一次 |
| 11281 / 11282 | 检查管理员失败（系统错误）/ **未通过管理员检查** | 提示"请把机器人设为群管理员" |
| 11265 | 机器人被封禁 | 停止调用 + 告警 |
| 1100301 / 1100104 | 调用方不是群成员 / 群已失效 | 清理该群配置 |
| 306001~306006 | 撤回相关（参数无效 / msgid 错误 / 取消息失败 / 无权限 / 撤回失败 / 取子频道失败） | 撤回失败 → 降级禁言 + 上报 |
| 40064004 / 40062003 | 超出撤回时限（>2 分钟）/ 无撤回权限 | 同上 |
| 40034100 / 40054002 | 主动消息超频控 / 机器人被禁言 | 退避 / 只做管理动作 |
| 40034005 | 回复 msg_id 已过期 | 放弃被动回复或改主动消息 |
| 12002 | 请求体错误 | 记录（多为插件构造 bug） |

**限频**：群信息/群状态/入群列表/禁言查询/成员详情/批量移除/黑名单查询 = 30 QPM；审批/禁言写入/自动审批策略/成员列表/黑名单写 = 60 QPM；发群消息 = 100 QPS；**撤回 = 10 QPS**。
**主动消息**（群）：单 Bot 30~60 qpm、单群 20 qpm、**每群每天 1000 条**。**被动回复**：5 分钟窗口、同一条消息最多 5 次。
**Intents**：除 GUILDS / PUBLIC_GUILD_MESSAGES / GUILD_MEMBERS 外均需申请；无权限会导致 websocket 报错断开（4014）。

## 3. 群管理接口清单

| # | 方法 | 路径 | 权限 | QPM |
| --- | --- | --- | --- | --- |
| 1 | GET | `/v2/groups/{gid}/info` | 仅白名单（11253） | 30 |
| 2 | GET | `/v2/groups/{gid}/bot_state` | 仅白名单（11253） | 30 |
| 3 | GET | `/v2/groups/{gid}/join_request_list`（cursor/limit≤50） | 群管理员 | 30 |
| 4 | POST | `/v2/groups/{gid}/approval_join_request/{member_openid}` | 群管理员 | 60 |
| 5 | GET | `/v2/groups/{gid}/restrict_chat_setting` | 群管理员 | 30 |
| 6 | POST | `/v2/groups/{gid}/restrict_chat_setting` | 群管理员 | 60 |
| 7 | GET | `/v2/groups/join_approval_strategy` | 文档未标 | 60 |
| 8 | POST | `/v2/groups/join_approval_strategy` | 文档未标 | 60 |
| 9 | PATCH | `/v2/groups/join_approval_strategy/{strategy_id}` | 文档未标 | 60 |
| 10 | DELETE | `/v2/groups/join_approval_strategy/{strategy_id}` | 文档未标 | 60 |
| 11 | POST | `/v2/groups/join_approval_strategy/{strategy_id}/execute` | 文档未标 | 60 |
| 12 | POST | `/v2/groups/join_approval_strategy/{strategy_id}/whitelist_users` | 文档未标 | 60 |
| 13 | GET | `/v2/groups/{gid}/members`（≤30 条/页） | 白名单 + **内邀** | 60 |
| 14 | GET | `/v2/groups/{gid}/members/{member_openid}` | 白名单 + 内邀 | 30 |
| 15 | POST | `/v2/groups/{gid}/batch_remove_members`（≤20） | 白名单 + 内邀 | 30 |
| 16 | GET | `/v2/groups/{gid}/member_blacklist`（limit≤100） | 白名单 + 内邀 | 30 |
| 17 | POST | `/v2/groups/{gid}/member_blacklist`（op add/del，≤20） | 白名单 + 内邀 | 60 |
| 18 | POST | `/v2/groups/{gid}/messages` | 文档未标 | 100 QPS |
| 19 | DELETE | `/v2/groups/{gid}/messages/{message_id}` | 管理员可撤回他人 | 10 QPS |
| 20 | POST | `/v2/groups/{gid}/files` / `upload_prepare` / `upload_part_finish` | 文档未标 | 50/10/10 QPS |

**字段要点**

- info：`group_name`、`group_finger_memo`、`group_class_text`、`group_tags[]`、`group_member_num`。
- bot_state：`member_openid`（机器人自身）、`joined_at`、`allow_proactive_msg`、**`recv_msg_setting`（all / only_mention / mention_and_context）**、**`member_role`（member / owner / admin）**。
- join_request_list 的 JoinRequest：`join_request_id`（审批必回传）、`risk_tips`（warning_tips / top_tips）、`union_openid`、`member_openid`、`username`、`apply_at`、`apply_source`（self_apply / invited）、`invited_by`、`bot`、`verify_info`（method / verify_message / review_qa_list[{question,answer}]）。
- 审批 body：`{op: approve|decline, join_request_id, reject_reason?, add_to_member_blacklist?}`。
- 禁言 GET：`global_rule.mode`（none/always/schedule）+ `schedule_rules[]` + `recurring_rules[]`（weekdays 1~7、start_time/end_time HH:mm，end<start 表示跨天）+ `members[]`（member_openid / mute_expire_at / username；**不含已过期**）。
- 禁言 POST：`members[{op: add|update|del, member_openid, mute_expire_at}]`，单次 ≤20，**最长 30 天**，add/update **只能操作普通成员**；**无接口可修改 `global_rule`（全员禁言只读）**。
- 策略：`group_openids` 与 `group_ids` 二选一（≤100 群），`is_enable`、`expire_at`（默认一年）、`remark`（≤255 汉字）；**每 Bot ≤20 个策略**；白名单单次 ≤10000、上限 10W；`execute` 为异步全量扫描（约 10 分钟）。
- 成员对象：`member_openid` / `username` / `member_role` / `bot` / `joined_at` / `union_openid`；黑名单对象：`union_openid` / `member_openid` / `username` / `banned_at` / `bot`。
- 撤回：管理员可撤回自己与**普通成员**的消息；超过 2 分钟不可撤回。
- 发消息：`msg_type` 0 文本 / 2 Markdown / 7 富媒体；被动用 `msg_id`（5 分钟、≤5 次）或 `event_id`（支持 INTERACTION_CREATE / GROUP_ADD_ROBOT / GROUP_MSG_RECEIVE）；相同 `msg_id + msg_seq` 重复发送会失败。

## 4. 群相关事件

| 事件 | Intent | 说明 |
| --- | --- | --- |
| GROUP_AT_MESSAGE_CREATE | 1<<25 | 群内 @机器人 的消息 |
| GROUP_MESSAGE_CREATE | 1<<25 | 群「接收全部消息」模式下的每条消息 |
| GROUP_ADD_ROBOT / GROUP_DEL_ROBOT | 1<<25 | 机器人被拉入 / 移出（字段 timestamp、group_openid、op_member_openid） |
| GROUP_MSG_RECEIVE / GROUP_MSG_REJECT | 1<<25 | 群管理员开启 / 关闭「接收全部消息」 |
| SUBSCRIBE_MESSAGE_STATUS | 1<<25 | 订阅授权状态变更 |
| GROUP_MEMBER_ADD / GROUP_MEMBER_REMOVE | **1<<24** | 成员入群 / 退群（timestamp、group_openid、member_openid、user_openid） |
| GROUP_JOIN_REQUEST | **1<<24** | 用户申请加群（仅机器人是管理员时可见） |

消息事件关键字段：`id`（消息 ID，用于回复与撤回）、`author`（member_openid / username / **member_role**）、`content`（**已去除 @机器人 前缀**）、`group_openid`、`timestamp`、`message_type`、`message_scene`、`attachments[]`（含 `asr_refer_text` 语音转写）、`mentions[]`、`ark_data`、`msg_elements[]`（message_type 0/3/101/102/103）。
⚠️ 文档提示：**相同 msg_id 可能重复推送**，需结合 `msg_seq` 去重。
⚠️ Intents 总表里只有 `1<<25`，`1<<24` 仅出现在 3 个成员事件页 → 可订阅性需实测。

## 5. AstrBot 对接实现细节

### 5.1 适配器与通道

```python
from botpy.http import Route

# GET
route = Route("GET", "/v2/groups/{group_openid}/info", group_openid=gid)
data = await event.bot.api._http.request(route)

# POST
route = Route("POST", "/v2/groups/{group_openid}/restrict_chat_setting", group_openid=gid)
await event.bot.api._http.request(
    route, json={"members": [{"op": "add", "member_openid": oid, "mute_expire_at": iso}]}
)
```

- `event.bot` 是 botpy `Client`；`event.bot.api._http` 是 `botpy.http.BotHttp`，内部持有 `Token`，会自动设置鉴权头并刷新 token（插件无需自管 appid/secret）。
- 定时任务里用 `context.get_platform_inst(platform_id).client` 拿同一个 client。
- `_http` 是私有属性 → 必须集中封装 + 启动自检 + 兜底自建 aiohttp 客户端（appid/secret 可从平台实例属性读）。
- 异常：`botpy.errors.*`（ForbiddenError / NotFoundError / ServerError ...）；AstrBot 官方实现对 5xx/超时用 tenacity 指数退避（最多 5 次）。

### 5.2 事件、LLM、存储、Pages 【实测 v4.27.3】

- 装饰器：`command(name, alias, priority)` / `command_group` / `regex` / `event_message_type` / `platform_adapter_type` / `permission_type` / `custom_filter` / `llm_tool` / 钩子 `on_llm_request / on_llm_response / on_decorating_result / after_message_sent / on_astrbot_loaded / on_plugin_error ...`。`priority` 默认 0，注册表按 `-priority` 排序（大者先跑）。
- 事件对象：`message_str / message_obj / unified_msg_origin / session_id / role / is_wake / is_at_or_wake_command`、`get_group_id() / get_sender_id() / get_sender_name() / get_platform_id() / is_admin()`、`plain_result() / image_result() / chain_result()`、`await event.send(MessageChain)`、`stop_event() / should_call_llm(bool)`、`await event.get_group()`、`set_extra/get_extra`。
- **没有 `event.reply()`**（引用回复用 `Comp.Reply(id=event.message_obj.message_id)`）；**没有 `on_config_updated`**（WebUI 保存配置 = 整插件重载）；`context.get_db_client()` 不存在，用 `context.get_db()`。
- `unified_msg_origin` 形如 `{platform_meta.id}:{MessageType}:{session_id}`，**首段是平台实例 ID（如"爱莉希雅"），不是适配器名** —— 原样存取，不要硬编码前缀。
- LLM：`await context.get_current_chat_provider_id(umo)`（async）→ `await context.llm_generate(chat_provider_id=..., prompt=..., system_prompt=..., contexts=[], image_urls=[])` → `resp.completion_text`；兼容 `await context.get_using_provider_async(umo=...)` → `prov.text_chat(...)`（`session_id` 参数已废弃）。
- 存储：`StarTools.get_data_dir()` → `data/plugin_data/<插件名>/`；KV 用 `put_kv_data / get_kv_data / delete_kv_data`。
- Pages：【实测】目录 `pages/<name>/index.html` 被自动发现；后端路由必须带 `/<plugin_name>/` 前缀，动态段 `<name>` / `<path:name>`；前端 `window.AstrBotPluginPage`（`ready() / apiGet / apiPost / upload / download / subscribeSSE`），endpoint 为插件内相对路径（不带插件名与前导斜杠）；`request` 提供 `query / json() / form() / files() / username`；响应 helper `json_response / error_response / file_response / stream_response`。
- 定时任务：`initialize()` 里 `asyncio.create_task`、`terminate()` 里取消；**没有 `on_schedule`**，也可用 `context.cron_manager`。
- 其它：禁止 requests（用 aiohttp/httpx）；数据写 data/ 不写插件目录；`from astrbot.api import logger`；用 `src` 子包时自行 `sys.path.insert`；提交前 ruff。
