## 0. 一句话

群级**「跟随全局」总开关**（醒目、默认开）：开着 = 本群全部规则取全局值，本群配置**保留但不生效**；
关掉 = 以关闭那一刻的当前全局值**全量固化**出本群配置、此后自治；
新群**不预生成任何配置文件**（不存在"配置不生效"的死数据）；审批模式不归该开关管辖。

## 1. 背景与问题

### 1.1 现状证据（当前代码事实）

| 层 | 位置 | 事实 |
| --- | --- | --- |
| 数据模型 | `src/models.py` `GroupConfig` | 每群配置里入群相关字段只有 `join_review_mode`；其余 `join_*` 全在全局 `default_settings()`（22 个键） |
| 判定引擎 | `src/join_review.py` `JoinReviewer` | 只有模式做「本群 → 全局」回退；门槛 / 答案校验 / 头像复核 / 置信度 / 拉黑 / 信任邀请人等一律读全局（`judge()` 入口一次读取） |
| 画像 | `src/profiles.py` `ProfileStore.get()` | `join_profile_enabled` 等读全局 |
| 模型选择 | `main.py` `_join_judge_call()` → `_llm_call(provider_setting=...)` | 按设置项名读全局 |
| API | `src/web_api.py` | 按群端点只有 `POST /groups/join_mode`（不接受空串=跟随全局）；`POST /joins/settings` 白名单键全部写全局，**白名单外的键被静默丢弃** |
| WebUI | `pages/manage/app.js` `viewJoins()` | 顶部有群选择器，紧随的「入群审批配置」卡却对所有群生效，卡片**无作用域标注** |
| 历史教训 | `src/store.py` `ensure_group()` 注释 | 早期版本曾在建群时复制全局值，后被**刻意回退**，理由是「改默认模式对已登记的群完全不起作用」 |

**结论**：「所有群一套规则」是设计如此 + UI 呈现误导，不是配置读取错误。
本需求提供「群级跟随/自治」的显式控制，并保留既有缺陷修复（作用域可见、未知键不静默丢弃）。

### 1.2 用户痛点

多群运营时各群定位不同：竞赛群要求高门槛与严格口令、水群宽松、专属群只收邀请。
现状无法按群差异化；同时又需要保留「改一次全局、所有群同步」的集中控制能力——两者必须兼得。

## 2. 评审确认的语义决定（2026-09-28，两轮定稿）

| 编号 | 决定 | 含义 |
| --- | --- | --- |
| D1 | **默认跟随全局** | 群级总开关 `join_follow_global` 默认开：新群、存量群一律取全局值；**不预生成配置文件** |
| D2 | **开关是门控，不是删除** | 开关开启时本群配置**原样保留但不生效**（可灰显可见）；关闭时生效；任何方向的切换都**不删除**配置数据 |
| D3 | **关闭 = 全量固化（已拍板选 X）** | 首次关闭（本群配置为空）时，以**关闭那一刻的当前全局值**生成本群配置 → 此后全局变更不影响本群；已有配置的群再次关闭 = **直接复活原配置**（不重新生成） |
| D4 | **字段级细粒度 = 编辑即固化 + 单向恢复** | 关态下改哪个字段就固化哪个；每个字段有「恢复跟随全局」按钮（删除该键回落全局）。不引入第二层"字段级开关"，状态由键存在性客观呈现 |
| D5 | **意图不靠值推断** | 「生效源」只由 开关状态 + 键存在性 决定；任何一方都不得用「值是否等于全局」推断意图（关闭瞬间固化值==全局值是常态） |
| D6 | **模式不归开关管辖** | `join_review_mode` 保持独立通道：默认跟随全局、可按群覆盖（既有行为不变）；纳入门控会让「开关默认开」瞬间吞掉存量已设模式，破坏零迁移等价。UI 补显式「跟随全局」选项（修复 §1.1 所述 API 缺陷），开关文案注明「不含审批模式」 |

## 3. 用户故事

| 编号 | 角色 | 故事 | 期望 |
| --- | --- | --- | --- |
| US-1 | 群主 | 竞赛群要 QQ 等级 ≥10，水群不设门槛 | 竞赛群关掉跟随、改门槛；水群保持跟随，互不影响 |
| US-2 | 群主 | 某群要专属入群口令 | 关跟随 → 设口令（其余字段固化为当前全局值）；不需要的字段逐个「恢复跟随」 |
| US-3 | 管理员 | 新群刚登记 | 默认跟随全局、**没有配置文件**；改全局它立即跟着变 |
| US-4 | 管理员 | 自治了一段时间的群想交回集中管理 | 打开开关：全局立即生效、**本群配置原封保留**；想反悔随时再关闭（原配置复活） |
| US-5 | 管理员 | 调整某项全局配置 | 界面按项显示「本项：N 群跟随 · M 群用本群值」，改之前就知道影响谁 |
| US-6 | 管理员 | 看待审列表与历史 | 能看到该判定依据「跟随全局」还是「本群配置」，自治时列出仍跟随全局的字段 |
| US-7 | 管理员 | 升级插件 | **零迁移**：升级前后行为逐键相同（默认开关开 = 现状） |
| US-8 | 群主 | 关闭跟随瞬间，本群配置值与全局一模一样 | 合法常态：此后改全局，本群**不**跟着变；界面上靠开关/徽标辨识，不靠值 |
| US-9 | 群主 | 自治后又想以「现在的全局」为基准重来 | 一键「以当前全局值重建本群配置」（P1），不必手动逐字段抄 |
| US-10 | 管理员 | 想设定「新群与所有跟随群默认用什么审批模式」 | 在管理台全局设置里直接改，不需要改配置文件/KV；改完跟随中的群立即生效 |

## 4. 功能需求

| 编号 | 优先级 | 需求 | 验收要点 |
| --- | --- | --- | --- |
| FR-1 | P0 | **存储**：`GroupConfig.join_follow_global: bool = True`（总开关）+ `GroupConfig.join_overrides: dict`（稀疏：键存在 = 本群固化值） | 旧数据缺字段 → 开关默认 `True`、配置空表 → 行为与现状等价 |
| FR-2 | P0 | **跟随总开关**：群级、醒目置顶；开 = 全局生效 + 本群配置保留停用；关 = 本群配置生效 | 开关切换**不删除**任何配置键；UI 两态都可见本群配置的存在 |
| FR-3 | P0 | **关闭语义（X）**：首次关闭（配置为空）→ 以关闭时刻当前全局值全量固化 17 键；配置非空 → 直接复活，不重新生成 | 关闭瞬间生效值不变；此后改全局该群不变；二次关闭用的是原配置（旧值），不由全局刷新 |
| FR-4 | P0 | **字段级**：关态下编辑即写入本群配置；每字段「恢复跟随全局」按钮删除该键回落全局 | 恢复后该字段随全局变化；再编辑即重新固化；无第二层开关概念 |
| FR-5 | P0 | **解析唯一入口**：`effective_join_settings(group_id)` 按公式合并 | 所有消费点只经此函数；合并不做等值比较 |
| FR-6 | P0 | **键分类白名单**：可固化 17 键 / 全局唯一 5 键，作为 API、UI、归一化的单一事实来源 | 三处引用同一定义，不各写一份 |
| FR-7 | P0 | **API**：`POST /joins/settings` 支持三类分群形态——`group_id` + `follow_global`（开关）、`group_id` + 若干可覆盖键（固化，**键平铺**、不引入名为 patch 的包装字段）、`group_id` + `reset`（恢复跟随，单键列表或 `"*"` 清空） | 非法键 400 且带键名（不静默丢弃）；服务端从不按值清理或生成 |
| FR-8 | P0 | **WebUI**：卡顶醒目开关；开态字段灰显 + 「本群配置已保留 N 项（未生效）」；关态可编辑 + 字段徽标（`本群` / `跟随`）；关闭时 toast 说明本次是"生成"还是"复活" | 两态的可编辑性、徽标、提示文案与 FR-2/FR-3 一致 |
| FR-9 | P0 | **影响面计数**：全局编辑区每项显示「本项：N 群跟随 · M 群用本群值」（按**键**统计：开态群、关态但该键已恢复跟随的群都计入"跟随"） | 改全局前能判断这一项影响多少群（NFR-6 的可见性保障） |
| FR-10 | P0 | **判定留痕**：审批记录新增 `settings_scope` | `"global"`（或 NULL 旧记录）= 跟随全局；`"off"` = 自治且全部字段固化；`"off\|k1,k2"` = 自治但这些字段仍恢复跟随 |
| FR-11 | P0 | **模型按群**：`join_llm_provider_id` 属可固化键，受开关门控 | 关态固化模型走本群模型；开态/恢复跟随走全局回落链 |
| FR-12 | P0 | **模式「跟随全局」选项**：`POST /groups/join_mode` 允许空串，UI 下拉补「跟随全局（当前：{全局模式}）」 | 修复既有缺陷；模式不受总开关影响（D6） |
| FR-13 | P1 | **展示**：`审核状态` 指令、待审/历史列表标注规则来源；配置卡列出「仍跟随全局的字段」 | 按作用域表述，不按值差异表述 |
| FR-14 | P1 | **维护操作**：「以当前全局值重建本群配置」（关态，覆盖重固化）、「清空本群配置」（`reset:"*"`，二次确认，永久删除） | 重建后逐键等于当时全局；清空后关态字段全部回落全局 |
| FR-15 | P0 | **全局入群审批模式编辑入口**：全局设置卡首个字段（`join_review_mode`，标注「全局·不分群」），随全局形态保存 | 改后新登记群与「跟随全局」的群立即生效，按群固定的群不受影响；按群下拉「跟随全局（当前：X）」同步；**字段规格表必须覆盖全部 `join_*` 键** |

## 5. 非功能需求

| 编号 | 需求 |
| --- | --- |
| NFR-1 | **零迁移**：旧 KV 无新字段 → 开关默认开、配置空 → 与现状逐键等价；不写迁移脚本、无需用户操作 |
| NFR-2 | **失败可见**：非法键 / 非法值必须返回明确错误并记 warning；禁止「静默丢弃」式兼容 |
| NFR-3 | **热生效**：保存/切换后下一次判定即用新值，无需重启 |
| NFR-4 | **多群隔离**：对 A 群的任何操作，B 群生效值逐键不变（用例强制） |
| NFR-5 | **等价基线**：开关全开且配置为空时，全链路行为与现状逐键等价（既有用例不改断言直接通过） |
| NFR-6 | **变更可见**：改全局只影响「跟随中的群」；全局编辑区必须显示影响面计数，发布说明写明新控制方式 |
| NFR-7 | **性能**：解析为内存 dict 合并，不引入额外 KV 读 |
| NFR-8 | **单点回滚**：删除两个新字段即整体回退旧版行为（回退需恢复 KV 备份） |
| NFR-9 | **意图不靠推断**：生效源只由开关状态 + 键存在性决定；值比较不得参与任何生效源决策（同值固化合法） |
| NFR-10 | **配置不丢失**：开关切换**永不**删除配置；单键删除**仅**由用户显式「恢复跟随」触发；整表删除**仅**由 `reset:"*"`（显式清空 + 二次确认）触发。任何其它路径（保存、切换、解析）都不得增删配置键 |

## 6. 范围外（Out of Scope）

- 官方「入群自动审批策略」的分群配置（平台侧为 Bot 级能力，见 `docs/平台能力调研.md`）；
- 轮询间隔按群（后台是单间隔调度任务，另立需求）；
- 画像采集的缓存天数 / 限频 / 并发分群（缓存键不带群、限频是全局闸门）；
- 发言审核（模式/阈值/处置矩阵/关键词）的分群；
- 跨群黑名单与白名单（已有独立机制）；
- **跨群批量开关**：默认即跟随、自治群是少数且可枚举，逐群操作可接受；若日后确有诉求再立项。

| S-5 | 「改全局」从静默生效变成**静默不生效**，会被当成故障；为此要再造批量跟随逃生口 | 消除：默认跟随恢复中心控制；影响面计数改为展示「自治群」（FR-9） |

## 8. 验收标准（AC）

- AC-1 新群默认跟随：改全局 → 新群生效值随之变化；群记录中**无配置文件生成**（US-3 / FR-1）；
- AC-2 首次关闭开关：生效值在关闭前后**不变**（固化值=当时全局），此后改全局该群不变；打开开关 → 全局立即生效且配置保留；再次关闭 → **原配置复活**（用的是首次关闭时的旧值，不被当前全局刷新）（FR-2/FR-3）；
- AC-3 存量群升级前后行为逐键相同（默认开关开 + 空配置 = 现状）（US-7 / NFR-1）；
- AC-4 关态下某字段「恢复跟随全局」→ 改全局该字段随之变化；再编辑该字段 → 重新固化并停止跟随（FR-4）；
