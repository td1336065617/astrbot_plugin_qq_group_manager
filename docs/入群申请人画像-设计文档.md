## 1. 总体方案

在**不改动审批协议**的前提下，向「申请 → 判定 → 审批」链路插入一个**画像采集层**，并让画像参与硬规则与 LLM 判定。

```
OneBot 加群请求事件 ─┐
                     ├─► feed_request()/join_request_list()  ← 现有
官方 join_request_list┘            │
                                   ▼
                    ┌──────────────────────────────┐
                    │ ApplicantProfileService       │  ← 新增
                    │  通道探测 / 缓存 / 限频 / 熔断 │
                    └──────────────┬───────────────┘
                                   │ request["profile"]
                                   ▼
                    JoinReviewer.judge()
                      ├ 硬规则（黑名单/bot/risk_tips）
                      ├ 画像硬规则（等级/账号年龄/QID）  ← 新增
                      ├ 资料缺失策略                     ← 新增
                      ├ 信任邀请人
                      └ LLM（prompt 注入画像 + 可选头像多模态）← 增强
                                   │
                                   ▼
                     approve_join_request / set_group_add_request  ← 现有
                                   │
                                   ▼
                    审计 join_requests（补画像列）→ WebUI / 指令 / 通知
```

设计原则：

1. **画像只做「加分项」**，采集失败一律降级，不阻塞审批（fail-open → 转人工）。
2. **能力差异显式化**：官方通道不发起任何画像请求，画像标记为 `source=official` 且 `degraded=true`。
3. **默认全关**：新增阈值默认 0/off，升级后行为与现版本一致。
4. **协议端差异可探测**：`qqLevel/reg_time` 属 NapCat 扩展，缺失时按「资料缺失」处理，不报错。

## 2. 领域模型

### 2.1 `ApplicantProfile`（新增，`src/models.py`）

```python
@dataclass(slots=True)
class ApplicantProfile:
    platform_id: str = ""
    kind: str = ""                 # onebot / official / null
    user_id: str = ""              # OneBot=QQ号；官方=member_openid
    nickname: str = ""
    avatar_url: str = ""
    qq_level: int | None = None    # OneBot: get_stranger_info.qqLevel
    qid: str = ""
    sex: str = ""
    age: int | None = None
    reg_time: int | None = None    # 注册时间戳（秒）
    account_age_days: int | None = None
    is_vip: bool = False
    vip_level: int = 0
    source: str = "none"           # onebot_stranger / official_request / cache / none
    degraded: bool = False         # 资料缺失或采集失败
    note: str = ""                 # 失败原因，用于审计与 UI 提示
    fetched_at: int = 0

    def to_dict(self) -> dict[str, Any]: ...
    @classmethod
    def from_dict(cls, payload: Any) -> "ApplicantProfile": ...
    @property
    def has_account_signals(self) -> bool: ...  # qq_level / reg_time 至少一项
```

画像以 `request["profile"]`（dict）形式随现有申请对象流转，**不改变 `join_request_list` / `approve_join_request` 的既有契约**，避免大面积签名改动。

### 2.2 `JoinDecision` 扩展（`src/join_review.py`）

新增字段：`gate: str = ""`（命中的门槛名，如 `account_age`）与 `profile: dict`（判定所用画像快照），便于审计与申诉回溯。

## 3. 采集层设计

### 3.1 通道接口扩展（`src/platforms/base.py` 的 `Channel` 协议）

```python
async def get_applicant_profile(self, request: dict, *, caller: str = "join_review") -> dict:
    """返回 ApplicantProfile.to_dict()；任何失败都返回 degraded 画像，不抛异常。"""
```

| 通道 | 实现 |
| --- | --- |
| `OneBotChannel` | 有 `user_id`（QQ 号）时调 `get_stranger_info(user_id, no_cache=False)`；拼头像；解析失败 / 字段缺失 → `degraded=True` |
| `OfficialChannel` | 由 `request` 直接构造：`nickname=username`、`user_id=member_openid`、`source="official_request"`、`degraded=True`、`note="官方接口不提供头像/等级"；**零额外请求** |
| `NullChannel` | 返回 `degraded=True, source="none"`（注意：`NullChannel.__getattr__` 返回的是「一调用就抛 `QQApiError`」的桩函数，**必须显式实现**才能真正降级） |

### 3.2 OneBot 字段映射

```
nickname       ← nickname or long_nick or remark
qq_level       ← qqLevel（NapCat 扩展，缺失为 None）
reg_time       ← reg_time（NapCat 扩展；缺失为 None）
account_age_days ← (now - reg_time) // 86400
qid/sex/age/is_vip/vip_level ← 同名（可选）
avatar_url     ← f"https://q1.qlogo.cn/g?b=qq&nk={qq}&s=640"
degraded       ← not (nickname and (qq_level is not None or reg_time is not None))
```

> 头像直链与 NapCat 内部使用同一 CDN（`q.qlogo.cn/headimg_dl`），无需协议端支持。

### 3.3 `ApplicantProfileService`（新增，`src/profiles.py`）

职责：缓存 / 限频 / 熔断 / 通道路由。构造参数：`channel_for: Callable[[platform_id], Channel]`、`store`、`logger`。

```python
async def get(self, group_id: str, request: dict) -> dict:
    platform_id = self.store.group(group_id).platform_id
    user_key = request.get("user_id") or request.get("member_openid")
    # 1) 内存 LRU + KV 持久缓存（TTL join_profile_cache_days）
    # 2) 限频：令牌桶 join_profile_qpm（默认 30），并发 join_profile_concurrency（默认 2）
    # 3) 熔断：连续 N 次失败 → 冷却 T 秒内直接返回 degraded
    # 4) 调用 channel.get_applicant_profile(request)
    # 5) 写缓存（仅缓存成功且 has_account_signals 的结果，避免缓存「空画像」）
```

缓存键：`f"{platform_id}:{user_key}"`；缓存内容为 `ApplicantProfile.to_dict()`（含 `fetched_at`）。
**只缓存成功画像**：失败结果不缓存，但计入熔断计数。

### 3.4 接入点

- `main.py` 初始化时构造 `self.profiles = ApplicantProfileService(...)`，并注入 `JoinReviewer(profile_getter=self.profiles.get)`。
- `JoinReviewer.poll_group()` 在 `judge()` **之前**调用 `profile_getter`（若已注入）；OneBot 事件路径同样经 `poll_group`，无需重复实现。
- 官方通道 `profiles.get` 直接构造官方画像，不触发网络请求（AC-4）。

## 4. 判定链改造（`src/join_review.py judge()`）

新顺序：

```
1. 本地黑名单                     （现有）
2. 跨群黑名单                     （现有）
3. bot 账号                       （现有）
4. risk_tips == top_tips          （现有）
5. 【新增】资料缺失策略            profile.degraded → pass | manual | decline
6. 【新增】画像硬规则              账号年龄 / QQ等级 / QID（按配置的 action）
7. 信任邀请人                     （现有）
8. LLM（prompt 注入画像，可选头像多模态）
```

### 4.1 画像硬规则

| 规则 | 配置 | 命中条件 |
| --- | --- | --- |
| 账号年龄 | `join_min_account_days`（0=关） | `account_age_days is not None and < N` |
| QQ 等级 | `join_min_qq_level`（0=关） | `qq_level is not None and < N` |
| QID 缺失 | `join_require_qid`（false=关） | `qid == ""` |

每条规则的 action 统一走 `join_gate_action`（`decline | manual | pass`，默认 `decline`）。
**数据缺失时不命中**（关键：`qq_level is None` 不触发等级规则），缺失由第 5 步统一处理，避免把「协议端不支持」误判为「可疑」。

理由文案模板：`"账号注册时间过短（{days} 天 < {limit} 天）"` 等，落库并展示给申请人（可选脱敏）。

### 4.2 LLM prompt 增强

`JOIN_USER_TEMPLATE` 追加画像区块：

```
【申请人画像】QQ等级={qq_level or 未知}；账号年龄={account_age_days or 未知}天；注册时间={reg_time or 未知}；QID={qid or 无}；性别={sex or 未知}
【画像完整度】{完整 / 缺失（原因）}
```

`JOIN_SYSTEM_PROMPT` 追加准则：

> - 账号年龄过短、等级过低、资料空白只作为**风险加分**，不得单独定罪；
> - 「画像缺失」是协议能力问题，不等于申请人可疑。

## 5. 头像多模态审核（P1）

### 5.1 现状约束

- `JoinReviewer.judge_call` 现签名为 `Callable[[str, str], Awaitable[str]]`，**无图片参数**。
- `main._join_judge_call` 内部构造 `ModerationRequest(text=user_prompt)`，`image_urls` 为空 → 当前无法送图。
- 内容审核链路已证明「HTTP(S) URL 直接作为 `image_urls` 传 `context.llm_generate`」可用（`main.py` 图片送审逻辑）。

### 5.2 设计

- `judge_call` 签名扩展为 `Callable[..., Awaitable[str]]`，调用时尝试 `judge_call(system, user, image_urls=[...])`，`TypeError` 时退回两参调用（保持向后兼容与可测试性）。
- `main._join_judge_call` 透传 `image_urls` 到 `ModerationRequest`。
- 触发时机由 `join_avatar_review` 控制：
  - `off`：不送图（默认）；
  - `approve_only`：仅当文本判定为 **approve** 且置信度低于 `join_avatar_only_below`（默认 0.95）时补一次头像复核 → 省 token，专治「文本正常但头像擦边」；
  - `always`：每次判定都带头像。
- 头像复核结论只用于**下调为 decline**（单向收紧），不用于把 decline 改成 approve，避免越权放行。
- 图片不可访问 / 模型不支持多模态 → 捕获异常，保留原文本判定结果，记 `profile.note`。

### 5.3 成本控制

- 复用内容审核的模型选择逻辑（`choose_provider_id`）。
- **待解决**：入群审批当前绕过 `Moderator` 的 QPM / 日预算 / 并发闸门（见第 10 节问题 3）。头像复核上线前，建议把入群 LLM 调用接入同一闸门，否则"always"模式可能放大 token 消耗。

## 9. 兼容与降级矩阵

| 场景 | 行为 |
| --- | --- |
| 官方通道 | 不调用画像接口；画像 `degraded=True`；硬规则不命中；LLM 不含等级/年龄；UI 标注原因 |
| OneBot + NapCat | 画像完整；硬规则与头像多模态可用 |
| OneBot + 标准协议端（无 qqLevel/reg_time） | 画像部分缺失 → `join_profile_missing` 策略；等级/年龄规则不命中 |
| 协议端请求失败/超时 | 不重试超过 1 次；计入熔断；本次按缺失策略 |
| 多模态模型不可用 | 保留文本判定，记录 note |
| 新入库旧数据 | 新列 NULL，UI 显示「无」 |

## 10. 实现问题清单（已发现的坑）

1. **OneBot 昵称恒为空**：`onebot.py feed_request()` 读 `raw.get("username")`，而 OneBot 加群请求事件无该字段；必须靠 `get_stranger_info` 补齐（顺带修掉这个既有 bug）。
2. **`judge_call` 不支持图片**：现有签名与 `_join_judge_call` 均无 `image_urls` 通道，头像多模态需先扩展该接口（且要兼容测试里的两参替身）。
3. **入群 LLM 调用未接入限频/预算**：`main._join_judge_call` 直接走 `_llm_call`，绕过了 `Moderator` 的 `llm_qpm_per_group` / `llm_daily_budget` / 并发闸门；"always"头像模式会放大消耗。
4. **`record_join` 是字段白名单**：新列必须同步加进白名单，否则画像写不进库（不易察觉）。
5. **`NullChannel.__getattr__` 是「必抛桩」**：未显式实现的新方法会返回一个必定抛 `QQApiError` 的异步桩，未知平台会在审批链上炸掉。
5b. **入群相关全局配置当前没有任何 UI 入口**：`join_review_mode` / `join_min_confidence` / `join_decline_blacklist` / `join_trust_inviter` / `join_poll_interval` 只存在于 `default_settings()`，WebUI 只能改「每群模式」→ 本次需在「入群审批」视图补配置区。
5c. **配置写入是「已存在键」白名单**：`PluginStore.update_settings()` 只接受 `k in merged`；且 `tests/test_ui_contract.py::test_policy_payload_keys_are_known_settings` 会校验前端 payload 的键必须在 `default_settings()` 中 → 新增配置必须**三处同步**（`default_settings` / `app.js` payload / `NUMERIC_BOUNDS`+`normalize_settings`）。
6. **`ChannelRouter` 的 `_active` 与定时轮询**：`_task_join_poll` 是后台任务，`_active` 可能是上次事件遗留的通道；画像必须走 `channel_for(platform_id)`（按群的 `platform_id`）而非 `self.api` 当前态。
7. **协议端扩展字段不可假定**：`qqLevel/reg_time/qid` 是 NapCat 扩展，需按「可能缺失」写解析，并对 `qqLevel` 可能为对象/字符串做宽进严出。
8. **设计文档遗留错误**：`docs/设计方案.md` 判定链写到「是否新号」，但官方通道无账号年龄数据源，需一并修正表述。
9. **缓存误伤**：若缓存了「失败的空画像」，会长期按缺失策略处理真实用户；因此只缓存成功画像。
10. **隐私**：画像属个人信息，`profile_json` 是否随 `retention_join_days` 一起清理？需确认（默认随申请记录清理）。

## 13. 已确认结论（v1.0 定稿）

| 决策 | 结论 | 对本设计的落地要求 |
| --- | --- | --- |
| 首版范围 | P0 + 头像多模态（FR-9） | §5 必须落地，且先解决 §10 问题 2/3（`judge_call` 图片通道、LLM 限频接入） |
| 资料缺失策略 | `join_profile_missing=manual` | §4 第 5 步默认转人工 |
| 硬门槛默认值 | 全关 | §7 默认值不变，仅提供能力，不预置阈值 |
| 展示范围 | 管理台完整、群内脱敏 | §8 中 WebUI 显示完整 QQ 号与头像；`join_list_text` 与通知沿用 `mask_openid` |
| 跨群联动 | 下一版 | FR-10 不进本期实施顺序 §12 |

> 风险提示：头像多模态与 `manual` 缺失策略都会增加人工/模型开销；上线后建议观察 `join_requests` 的 `decided_by` 分布与 LLM 日调用量，再决定是否收紧门槛。
