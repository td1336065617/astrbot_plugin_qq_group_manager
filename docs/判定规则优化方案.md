# 判定规则优化方案（v0.4 设计草案）

> 背景：生产环境实测 `珈裙苓资料123456` 这类**形近字混淆广告**没有被判定、也没有被送审。
> 本文先做现状诊断与方案设计；**代码改动等确认后再做**。
> 关联文档：`docs/设计方案.md`（§5 LLM 审核、§6 处置）、`docs/平台能力调研.md`

---

## 实施状态（v0.4.0，2026-09-13 已落地）

本文方案已按下列决策实现并部署：

| 决策项 | 结论 |
| --- | --- |
| 默认送审条件 | `["rule_hit", "risk>=60"]`（阈值 60；闲聊仍不送审） |
| 变体/模板命中的处置 | **只送审**；LLM 判定为违规后，按判定到的类别与严重度走处置矩阵 |
| pypinyin | 允许使用：作为**可选依赖**，已安装则启用同音匹配，未安装自动跳过 |
| 覆盖类别 | 广告引流 / 诈骗赌博 / 涉黄（内置模板与词表）；辱骂类继续交给 LLM 判定 |
| 形近字表 | 内置基线 + WebUI「规则增强」可增删 |
| 同文案多号刷屏 | 已实现（骨架文本去重，窗口与人数阈值可配） |

实测（本机）：`珈裙苓资料123456` 由"零信号"变为 **骨架命中 + 风险分 100 → 送审**；
回归语料 33 条正样本送审率 100%、48 条负样本误送审率 0%（见 `tests/test_rule_corpus.py`）。

## 0. 结论速览

1. **没命中的原因不是 LLM 不行，而是这条消息根本没走到 LLM**：本地规则层零信号 → 送审条件（默认 `rule_hit`）不满足 → 直接 return。
2. 现有规则层只有三类信号：**精确子串**、**正则**、以及少数内置检测（外链 / 联系方式 / 重复字符 / 超长 / 刷屏）。**对形近字、插符号、全角、同义改写完全无感**。
3. 优化方向是**两件事一起做**：① 让规则层"看得见变体"（归一化 + 形近字表 + 广告模板 + 风险分）；② 让送审条件能用"风险分"表达，从而**既不放过变体，也不给纯聊天烧 token**。

## 1. 现状诊断

### 1.1 当前判定链路（三级）

```text
群消息
 ├─ 1. 本地规则层 RuleEngine（零成本，纯字符串）
 │     硬规则命中 → 直接判 violation（source=rule, conf=1.0），动作取规则自身配置，**不调 LLM**
 │     软规则命中 / 内置检测有信号 → 只作为"送审理由"
 ├─ 2. 送审条件 should_send()（默认 send_conditions = ["rule_hit"]）
 │     任何本地信号为空 → **直接 return，调用 LLM 的机会都没有**
 └─ 3. LLM 判定（严格 JSON + 置信度门槛）
```

### 1.2 实测证据（本仓库 RuleEngine 直接跑出来的结果）

| 输入 | 命中硬规则 | 是否有本地信号 | 是否送审 |
| --- | --- | --- | --- |
| `加群领资料` | 是 | 是 | 是（但被硬规则短路） |
| `加群领资料123456` | 是 | 是 | 是（短路） |
| **`珈裙苓资料123456`** | **否** | **否（摘要为空）** | **否** |
| `加 群 领 资 料` | 否 | 否 | 否 |
| `加-群-领-资-料` | 否 | 否 | 否 |
| `ｊｉａ群领资料`（全角） | 否 | 否 | 否 |
| `进群领取资料`（同义改写） | 否 | 否 | 否 |
| `裙苓资料`（部分形近） | 否 | 否 | 否 |

**根因**：硬规则是 `pattern in text` 的**精确子串匹配**；内置的"联系方式"正则要求数字后跟"群/加群"（`123456` 结尾不满足），"外链"要求 http(s)/域名。于是变体广告**既没命中规则，也没触发任何内置检测** → 不送审。

### 1.3 现有规则层能力清单

| 能力 | 现状 | 缺口 |
| --- | --- | --- |
| 关键词（literal） | 精确子串（大小写不敏感） | 变体、插符号、全角、同义改写 |
| 正则（regex） | 用户自写，编译失败静默跳过 | 普通用户写不出覆盖变体的正则 |
| 外链 | http(s) / www. / 常见短链域名 | 纯文本"加 wx 领取"、图片二维码 |
| 联系方式 | 扣扣/QQ/微信/手机号/数字+群 | 中文数字、全角、拆分号码、拼音（weixin） |
| 刷屏 | 60 秒内同人发言数 | 内容维度的重复刷屏（同文案多号） |
| 超长 / 重复字符 | 阈值判断 | — |

## 2. 送审策略澄清（回答"没命中硬规则的都会送审吗？"）

**不是。** 默认只送"本地有信号"的消息：

| `send_conditions` | 送审范围 | 相对成本 | 适用 |
| --- | --- | --- | --- |
| `rule_hit`（**默认**） | 命中硬/软规则，或内置检测有信号（外链/联系方式/重复/超长/刷屏） | 极低 | 省钱，但**变体广告会漏**（当前问题） |
| `has_link` / `long_text` / `new_member` / `flood` | 对应条件命中 | 低 | 针对性补漏 |
| `all` | **每条群消息都送** | 高（token 随消息量线性增长） | 强监管群 |
| `risk>=N`（**本方案新增**） | 本地风险分 ≥ N | 低且可调 | **推荐**：变体广告有分→送审，纯聊天无分→不送 |

> 你线上当前是默认 `rule_hit`，所以"闲聊"不会送审 —— 这是刻意的成本控制；问题在于**规则层对变体没信号**，而不是"送审条件太严"。

---

## 3. 优化目标与不变量

**目标**

- G1 形近字 / 同音字 / 插符号 / 全角 / 拆分数字 的广告**能被识别**（先送审，必要时直接处置）。
- G2 纯聊天消息在默认配置下**仍然不送审**（成本不上升）。
- G3 判定**可解释**：命中哪条规则、原文如何归一化、风险分怎么构成，都要能看到。
- G4 **不误伤**：正常聊天（含"资料""加群"这类词出现在正常语境）不因归一化被误判。

**不变量**

- 现有 `literal` 规则行为不变（精确匹配仍精确）。
- 插件仍**零第三方依赖**（拼音方案见 §5.1，默认不引入）。
- 审计、处置、dry-run、能力降级等既有语义不变。


## 5. 详细设计

### 5.1 文本归一化管线（新增模块 `src/normalize.py`）

对每条消息生成 3 个视图，**规则同时对多个视图求值**：

| 视图 | 处理 | 例子 |
| --- | --- | --- |
| `raw` | 原样（等于当前行为） | `珈裙苓资料123456` |
| `compact` | NFKC（全角转半角、兼容字符归一）→ 转小写 → 去零宽字符/变体选择符 → 去空白与干扰符（点、横线、下划线、星号、间隔号等） | `jia群领资料123456` |
| `skeleton` | 在 compact 基础上做**形近字/同音字映射**，再去除非中日韩与字母数字字符 | `加群领资料123456` |

**形近字/同音字表**（KV 可维护；内置一份高频广告字表）：

```text
加 ← 珈 伽 茄 家 佳 枷
群 ← 裙 羣 麇
领 ← 苓 伶 玲 岭 呤
资 ← 咨 姿 滋 兹
料 ← 廖 疗 聊
微 ← 薇 巍 溦     信 ← 芯 薪 馨
扣扣/抠抠/kou/qq/q·q → 联系类信号
```

**拼音方案（可选，默认关闭）**

- 方案 A（默认，零依赖）：仅用内置形近/同音字表 + 常见拼音缩写表（jiaqun、wx、vx、qq、v信）。
- 方案 B（开关 `pinyin_enabled`）：若运行环境**已安装** `pypinyin` 则启用整句同音匹配（`珈裙苓` → jia qun ling 与 `加群领` 同音）；未安装时自动跳过，**不写入 requirements.txt**，保持零依赖原则。

### 5.2 规则类型扩展

| type | 语义 | 用途 |
| --- | --- | --- |
| `literal`（现有） | 精确子串 | 兼容存量规则 |
| `normalized`（**新增，新建规则默认它**） | 在 compact + skeleton 上做子串匹配 | 一条 `加群领资料` 即可覆盖"珈裙苓资料""加 群 领 资 料""加-群-领-资-料" |
| `regex`（现有） | 额外在 compact 文本上跑一遍 | 高级用户 |
| `fuzzy`（**新增**） | 编辑距离 ≤ N（默认 1，模式长度 ≥ 3） | 少量错别字（如"加群领资枓"）；**不指望它覆盖整词变体** |
| `template`（**新增**） | 组合式广告模板，见 §5.3 | 变体识别的**主力兜底** |
| `pinyin`（可选） | 同音匹配 | 见 §5.1 方案 B |

### 5.3 广告模板规则（变体识别主力）

> 实现现状（v0.5.0）：内置 8 条模板 —— 拉群引流、黑话引流、深夜福利引流、盗版资源贩卖、召唤式引流、
> 私聊引流、兼职刷单、赌博引流、涉黄引流；词表分三类：**引导动作词**（去哪里）、**诱饵资源词**（给什么）、
> **黑话标记词**（懂的都懂 / 自取 / 车牌 / 稳赚不赔 …）。模板命中只送审、不直接处置；
> **同一个词不能同时满足模板的两个分组**（避免"车牌号我记不清了"这类正常句自匹配）。


不再依赖"某个具体词"，而是识别**广告的结构**：

```text
template = {
  "id": "ad_invite",
  "name": "拉群引流",
  "all_of": [
    {"any_of": ["加群", "进群", "入群", "拉群", "扫码进群", "jiaqun"]},
    {"any_of": ["资料", "福利", "资源", "教程", "答案", "兼职", "返利"]}
  ],
  "score": 40,
  "category": "广告引流",
  "severity": 4,
  "action": ["warn", "recall"]
}
```

- 每个 `any_of` 命中得一份分，全部命中则 `all_of` 成立；
- 命中模板 → 产生**软命中 + 风险分**（默认只送审；达到阈值可选直接处置）；
- 内置默认模板 4 条：拉群引流、私聊引流、兼职刷单、返利诈骗（后续可在 WebUI 增删）；
- 模板在 WebUI「关键词 → 广告模板」页签维护（M2）。

### 5.4 风险分与送审条件

**风险分**（0~100，累加后截断）：

| 信号 | 分值 |
| --- | --- |
| 精确命中硬规则 | 100（直接违规，不送审） |
| 骨架/归一化命中硬规则 | +70 |
| 命中广告模板 | +40 |
| 含外链或短链 | +25 |
| 疑似联系方式（含变体/拼音） | **+60**（单独即达阈值） |
| 数字串与"群/资料/加"共现 | 6~7 位 +20；**8 位以上 +60** |
| 60 秒内发言达刷屏阈值 | +20 |
| 含图片且 image_review 非 off | **+60** |
| 纯闲聊、无任何信号 | 0 |

**送审条件新增取值**：`risk>=N`（已实现）、`has_image`、`has_contact`、`ad_template`。
**当前默认**：`send_conditions = ["rule_hit", "risk>=60"]` —— 闲聊不送审，变体广告进 LLM。

### 5.5 处置与置信度（避免误伤）

- **精确命中**（literal/normalized 与规则词一致）：confidence = 1.0，按规则动作**直接处置**（现状）。
- **骨架 / 模板 / fuzzy 命中**：confidence = 0.75~0.9，默认动作**降一档**（先警告 + 送审，由 LLM 复核后决定是否撤回/禁言）；
  仅当规则显式配置动作**且**打开新开关 `auto_enforce_normalized`（默认 off）时才直接处置。
- 审计与申诉记录里保存：原文、compact、骨架、命中依据（规则/模板/分值明细），便于复核与调参。

### 5.6 LLM 侧与图片联动

- system 提示词增加一段：**识别规避写法（形近字、同音字、插符号/空格、全角、中文数字、拆分号码、拼音替代）**；
- user 模板的"可疑点"追加：骨架归一化命中的规则 + 风险分及其构成；
- 含图片且风险分达阈值时，按 `image_review` 把图片一并送审（识别二维码与图片内联系方式）。

## 6. 数据与配置设计

**KV 新增键**

| 键 | 内容 |

| `send_conditions` | 现为 rule_hit，建议 rule_hit + risk>=40 | 见 §5.4 |

## 9. 验证方案

1. **回归语料集**（新增 `tests/data/rule_corpus.json`）
   - 正样本 ≥ 25 条：形近字、插符号、全角、拆分数字、中文数字、拼音缩写、模板变体、图片说明文本；
   - 负样本 ≥ 40 条：正常聊天（含"资料""加群""领"等词出现在正常语境）、技术讨论、非广告链接分享、代码片段；
   - 指标：**正样本送审率 ≥ 95%**、**负样本误送审率 ≤ 5%**、**精确命中不回归**。
2. **单元测试**：归一化与骨架映射、模板组合判定、风险分累加、送审条件解析（含 risk>=N）、模糊匹配边界、
   `normalize_enabled=false` 时行为等价于旧版。
3. **真机验证**：小号发 `珈裙苓资料123456`、`加 群 领 资 料`、`进群领取资料`、含二维码图片；
   观察审核事件里的 source（rule/llm）、category、动作与风险分。

## 11. 风险与取舍

| 风险 | 说明 | 对策 |
| --- | --- | --- |
| 形近表膨胀导致误伤 | 例如"苓"出现在正常人名 | 字表只用于骨架视图；骨架命中默认只送审 + 警告 |
| 归一化掩盖差异 | "加 群"与"加群"等价后可能误判正常断句 | 只用于匹配；审计保留原文与差异，便于复核 |
| 拼音依赖 | pypinyin 是第三方库 | 默认关闭；未安装自动跳过；不写入 requirements.txt |
| 送审量上升 | 勾选 risk>=40 后变体广告会送审 | 阈值可调 + 采样率 + 缓存 + 日预算（既有闸门都在） |
| 模板误伤正常讨论 | 例如真的在聊"进群领资料"的活动 | 模板默认只送审不直处置，由 LLM 复核 |
