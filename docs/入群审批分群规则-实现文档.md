**（b）`GroupConfig` 两字段与容错**：

```python
@dataclass(slots=True)
class GroupConfig:
    ...
    #: 群级「跟随全局」总开关：True（默认）= 全部规则取全局值，本群配置休眠
    join_follow_global: bool = True
```

`from_dict()` 追加（**只归一、不告警**——该函数没有 logger，告警在 `store.load()` 侧做，见 §2.4）：

```python

overrides_raw = payload.get("join_overrides")
```

### 2.2 `src/store.py` 模块级函数

**放 `store.py` 而不是 `models.py` 的原因**：归一化管线 `normalize_settings()` 定义在 `store.py`，
若放 `models.py` 会反向 import → 循环导入（复盘发现的坑 #1）。

```python
def snapshot_join_overrides(global_settings: Mapping[str, Any]) -> dict[str, Any]:
    """以「关闭开关那一刻」的全局配置生成本群固化配置（仅在配置为空时调用）。"""
    base = default_settings()
    base.update(dict(global_settings))
    normalized = normalize_settings(base)
    return {key: normalized[key] for key in JOIN_GROUP_OVERRIDABLE_KEYS}


def _normalize_overrides_patch(raw, global_settings) -> dict[str, Any]:
    """校验 + 归一化一次分群写入；非法键 → ValueError（调用方转 400）。"""
    unknown = sorted(key for key in raw if key not in JOIN_GROUP_OVERRIDABLE_KEYS)
    if unknown:
        raise ValueError("不可分群配置的键：" + ", ".join(unknown))
    base = default_settings()
    base.update(dict(global_settings))
    base.update(raw)
    normalized = normalize_settings(base)
    return {key: normalized[key] for key in raw}
```

## 4. S3：API（`src/web_api.py`）

### 4.1 `joins_settings()` 重写

**先抽纯函数再接线**（可测性：handler 依赖模块级 `request` 全局，无法直接单测——既有测试对
Web 层全部采用源码契约风格的原因即在此）。payload 解析与校验抽成模块级纯函数：

```python
# src/web_api.py 模块级（或 src/utils.py）——纯函数，便于单测
class JoinsSettingsCommand(NamedTuple):
    scope: str                      # "global" | "group"
    group_id: str                   # 分群形态必填；全局形态为 ""
    follow_global: bool | None      # 分群 · 开关形态；其余为 None
    patch: dict[str, Any]           # 全局 22 键 或 分群固化键（平铺）
    clear: list[str]                # 分群 · 恢复跟随（["*"] 已展开为全部可固化键）

def parse_joins_settings_payload(payload: dict) -> JoinsSettingsCommand:
    """三形态解析 + 六类校验；任何非法输入 → ValueError（message 含具体键名）。"""
```

规则（与设计 §7.1 错误表逐行对应）：

1. 未知键（∉ `全局22键 ∪ OVERRIDABLE ∪ {group_id, follow_global, reset}`）→ `ValueError("未知配置键：…")`；
2. 无 `group_id`：`follow_global`/`reset` 出现 → `ValueError("follow_global / reset 必须与 group_id 一起提交")`；
   空 patch → `ValueError("没有可保存的配置键")`；
3. 有 `group_id`：`follow_global` 与 `reset`/覆盖键互斥 → `ValueError("follow_global 不能与 reset / 覆盖键同时提交")`；
4. `follow_global` 非 `bool`（含 `"false"` 字符串）→ `ValueError("follow_global 必须是布尔值")`（坑 #6）；
5. `reset` 非法形态 / 非白名单键 → `ValueError`；字符串仅接受 `"*"` 并展开为全部可固化键；
6. 分群固化键经 `_normalize_overrides_patch` 同款白名单校验（不在解析层归一化，归一化留在 store 层，避免两处实现）。

handler 只做四件事（**薄壳**）：

```python
async def joins_settings(self):
    if not self._service_ready(): return error_response("插件尚未初始化完成，请稍后重试")
    try:
        cmd = parse_joins_settings_payload(await request.json(default={}))
    except ValueError as exc:
        logger.warning("joins/settings 被拒：%s", exc)
        return error_response(str(exc))
    if cmd.scope == "global":
        settings = await self.service.store.update_settings(cmd.patch)
        return json_response({"settings": {k: settings.get(k) for k in cmd.patch}, "group_id": None})
    if self.service.store.group(cmd.group_id) is None:
        return error_response("群未登记：" + cmd.group_id)
    try:
        if cmd.follow_global is not None:
            await self.service.store.set_group_follow_global(cmd.group_id, cmd.follow_global)
        else:
            await self.service.store.update_join_overrides(cmd.group_id, cmd.patch, clear=cmd.clear)
    except ValueError as exc:
        logger.warning("joins/settings 分群写入被拒：%s", exc)
        return error_response(str(exc))
    # ④ 变更事件（设计 §8.2）：仅分群形态发布，供 WebUI 日志中心可见
    self.service.bus.publish("audit", {
        "kind": "join_settings_override",
        "group_id": cmd.group_id,
        "action": "follow" if cmd.follow_global is not None else ("clear" if cmd.clear and not cmd.patch else "patch"),
        "ts": to_iso(),
    })
    return json_response({"group_id": cmd.group_id,
                          "scope": self.service.store.join_settings_scope(cmd.group_id)})
```

- `KNOWN_KEYS` / 全局键集合由 `models.py` 元组 + `default_settings()` 组装，**不硬编码字符串副本**；
- store 层的 `ValueError` 是第二道防线（绕过 parser 直调 store 也安全）；
- 事件用**源码契约用例**断言（handler 无法直接单测）：`web_api.py` 含 `"join_settings_override"`；
- 导入补充：`web_api.py` 现只 `from .utils import now_ts`，事件 `ts` 与 `main.py` 的事件口径一致需 `to_iso`
  → 改为 `from .utils import now_ts, to_iso`。

## 5. S4：WebUI（`pages/manage/app.js` → `viewJoins`）

### 5.1 状态与数据流

```js
// 模块内状态（viewJoins 局部）
let scope = null;             // GET joins?group_id= 的 scope
let dirty = new Set();        // 编辑过的键（编辑检测，非意图判断）
let pendingReset = new Set(); // 点了「恢复跟随」的键（随保存提交）
let loadedValues = {};        // 打开/重载时每个字段的显示值
```

载入顺序：`loadConfig()`（全局 settings / options / groups）→ `GET joins?group_id=`（scope）→ 渲染。
任何保存/开关成功后：清空 `dirty/pendingReset` → **重拉 scope 对账**（以服务端为准）。

### 5.2 渲染规则（设计 §9.3 的落地）

| 分支 | 实现 |
| --- | --- |
| 开态 | 每字段 `input.disabled = true`；值 = `settings[k]`；徽标 `全局`；`k ∈ own_keys` 时徽标后追加「本群已保留（未生效）」 |
| 关态 · 固化键 | 可编辑，值 = `scope.overrides[k]`；徽标 `本群` + 「恢复跟随」按钮 |
| 关态 · 跟随键 | 可编辑，值 = `settings[k]`；灰徽标 `跟随`；`input.title = '修改后将固化为本群配置'` |
| 不分群键 | 只读，灰徽标 `全局·不分群` |
| 关态且 `own_keys` 为空 | 卡内提示条：「本群配置为空，所有字段当前跟随全局；编辑任一字段即开始固化」 |

徽标用 `<span class="scope-badge">`；开关复用既有 `.switch` 容器类（`style.css` 中已存在）。

### 5.3 事件与提交

**编辑**：`input.oninput/ onchange → dirty.add(k)`（不做任何值比较逻辑）。

**保存（关态）**：

```js
const payload = { group_id: gid };
for (const k of dirty) payload[k] = readValue(k);          // 只提交编辑过的键
if (pendingReset.size) payload.reset = [...pendingReset];  // 显式恢复跟随
if (Object.keys(payload).length === 1 && !payload.reset) { toast('没有需要保存的修改'); return; }
await bridge.apiPost('joins/settings', payload);           // 成功 → toast('本群配置已保存') → 对账重载
// 失败：toast 展示后端 400 message 原文（含键名），禁止只显示「保存失败」（NFR-2）
```

> **绝不全量提交**：否则 `pendingReset` 的字段会被静默重新固化（设计 §9.4 / 风险 R6）。

**恢复跟随**：按钮只 `pendingReset.add(k)` + 徽标即时变灰，**随下次保存生效**（不单独发请求）。

**总开关**：

```js
if ((dirty.size || pendingReset.size)
    && !confirm('有未保存的修改，切换开关将丢失，继续？')) { 恢复开关原状态; return; }
// ↑ 括号必须有：&& 优先级高于 ||，漏括号会变成 dirty.size || (pendingReset.size && confirm)，
//   即「只编辑过字段未点恢复」时跳过确认直接丢失（本表自己就差点犯的优先级错误）
const firstClose = scope.follow_global && scope.own_keys.length === 0;   // 用切换前的 scope 快照
await bridge.apiPost('joins/settings', { group_id: gid, follow_global: checked });
toast(checked ? `已切换为跟随全局；本群配置（${scope.own_keys.length} 项）已保留，可随时切回`
              : (firstClose ? '已以当前全局值生成本群配置（17 项）；此后全局变更不再影响本群'
                            : `已启用本群配置（${scope.own_keys.length} 项）；内容为上次固化的值`));
对账重载();
```

**离开保护（实现期由「三入口弹确认」升级为「按群暂存」，设计 §9.2/§9.4 已同步）**：
编辑态存 `state.joinEdits[gid] = { dirty, reset }`，任何重渲染后自动恢复（切群 / 应用模式 /
拉取 / 审批都不丢编辑）；仅总开关切换清空该群暂存并在 toast 明示；
「放弃修改」按钮二次确认后清除；开态渲染不采用暂存值作初值（防御陈旧上下文）。
> SSE 实时订阅只写文本框、**不触发整页重渲染**（已核实）。

**全局态卡**：沿用现有 22 字段表单与 `apiPost('joins/settings', {...})` 平铺提交（**保持缩进 8 空格**，
见 §7.2 契约用例）；每字段旁渲染影响面小字：

```
本项：${stats[k].follow} 群跟随 · ${stats[k].own} 群用本群值
```

保存前 `toast('将影响 N 个跟随本项的群；M 群使用本群值，不受影响')`。
