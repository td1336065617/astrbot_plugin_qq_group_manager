## 1. 范围与分层

```
                 ┌────────────────────────────────────────────────┐
  存储层         │ KV settings                 全局（唯一权威来源） │
                 │ KV groups[gid]                                             │
                 │     .join_follow_global  群级总开关，默认 True（门控）      │
                 │     .join_overrides      稀疏配置：键存在 = 本群固化值      │
                 │     .join_review_mode    模式通道（不归开关管辖，D6）        │
                 └───────────────┬────────────────────────────────┘
                                 │ 唯一解析入口 + 开关状态机
  解析层         effective_join_settings(gid)      生效值（公式见 §4.1）
                 join_settings_scope(gid)          作用域（供 UI）
                 join_follow_stats()               影响面计数
                 update_join_overrides(gid, patch, clear)
                 set_group_follow_global(gid, on)  开关转换（§3）
                 snapshot_join_overrides(global)   关闭时固化（模块级函数）
                                 │
                 ┌───────────────┼───────────────────────────┐
  消费层         │               │                           │
   JoinReviewer.judge    ProfileStore.get        _join_judge_call（LLM 模型）
   门槛/答案/头像/阈值/拉黑   画像开关                 join_llm_provider_id
```

约束：

1. **存储**：`join_overrides` 只存本群固化的键；开关只做门控，**任何方向的切换都不删除配置**（NFR-10）；
2. **解析**：全插件只允许一个合并函数，任何消费点不得自行读全局 `join_*` 拼配置；
3. **意图**：生效源只由「开关状态 + 键存在性」决定，不做任何等值比较（NFR-9）；
4. **无迁移**：旧数据缺字段 → `join_follow_global=True` + `join_overrides={}` = 现状行为，不需要迁移代码（NFR-1）。

## 2. 数据模型

### 2.1 `GroupConfig` 字段

```python
@dataclass(slots=True)
class GroupConfig:
    ...
    #: 群级「跟随全局」总开关：True（默认）= 全部规则取全局值，本群配置保留但不生效
    join_follow_global: bool = True
    #: 本群固化配置（稀疏）：键存在 = 本群自己的值；键缺失 = 该键跟随全局（仅关态参与生效）
    join_overrides: dict[str, Any] = field(default_factory=dict)
```

- 存放位置：复用现有 `KV groups[group_id]`，**不新增 KV 键**；
- **禁止走通用入口写这两个键**：`update_group()` 的通用 patch 必须显式拒绝
  `join_follow_global` / `join_overrides`（防御：绕过状态机会产生"开关显示关但配置为空"之类的
  未定义路径）。所有写入只能经 §3.2 / §4.1 的专用方法；配防御用例；
- **新群不预生成配置**：`ensure_group()` 无需改动（dataclass 默认值即 D1），`join_overrides` 保持空表，
  直到用户首次关闭开关（§3.2）才生成——不存在「默认勾选跟随但配置文件不生效」的死数据；
- 无时间戳字段：「从未初始化」与「主动清空」在本模型下**行为完全相同**（关态空表 = 字段全部跟随全局），
  无需区分（对比 v1.0 被废弃的时间戳方案）。

### 2.2 键分类白名单（单一事实来源）

```python
#: 可固化到本群的入群审批配置键（决策类，17 个）
JOIN_GROUP_OVERRIDABLE_KEYS: tuple[str, ...] = (

    "join_decline_blacklist",     # 拒绝时是否拉黑
    "join_trust_inviter",         # 信任邀请人直接放行

    "join_min_account_days",      # 账号年龄门槛
    "join_min_qq_level",          # QQ 等级门槛
    "join_require_qid",           # 要求 QID
    "join_gate_action",           # 门槛命中动作 decline/manual/pass
    "join_profile_missing",       # 资料缺失策略 manual/pass/decline
    "join_avatar_review",         # 头像多模态复核 off/approve_only/always
    "join_avatar_only_below",     # 头像复核触发阈值
    "join_expected_answer",       # 期望答案（子串）
    "join_answer_keywords",       # 答案关键词（任一命中）
    "join_answer_regex",          # 答案正则
    "join_answer_action",         # 答案校验未通过动作
    "join_answer_case_sensitive", # 答案校验是否区分大小写

#: 全局唯一、不分群的入群相关配置（5 个，含各自理由）
JOIN_GLOBAL_ONLY_KEYS: tuple[str, ...] = (
    "join_review_mode",         # D6：走 GroupConfig.join_review_mode 独立通道，不归总开关管辖
    "join_poll_interval",       # 后台为单间隔调度任务
    "join_profile_cache_days",  # 画像缓存键为 platform:uid，不带群
    "join_profile_qpm",         # 全局令牌窗口
    "join_profile_concurrency", # 全局信号量

```

| 键 | 不分群理由 |
| --- | --- |
| `join_review_mode` | D6：纳入门控会让「开关默认开」吞掉存量已设模式；保留独立通道 + 显式「跟随全局」选项 |
| `join_poll_interval` | 调度器只有一个轮询任务与一个间隔，按群拆分需改任务模型（范围外） |
| `join_profile_cache_days` | 缓存键跨群共享，同申请人出现在两群时会互相污染 |
| `join_profile_qpm` / `join_profile_concurrency` | 全局令牌窗口与信号量是资源闸门，分群会破坏预算/熔断语义 |

**白名单的使用方（必须同源，禁止硬编码副本）**：

1. `src/store.py` `snapshot_join_overrides` / `_normalize_overrides_patch`（**注意：这两个函数必须放
   `store.py` 而非 `models.py`**——归一化管线 `normalize_settings()` 定义在 `store.py`，
   反向 import 会造成循环导入；白名单元组本身定义在 `models.py`）；
2. `src/store.py` 写入/解析的键过滤；
3. `src/web_api.py` 全局路径与分群路径的键校验；
4. `pages/manage/app.js` 字段集（经 `GET /config` 的 `options` 下发）；
5. 测试：三向一致性用例（设置项 ↔ 页面字段 ↔ 白名单）。

### 2.3 归一化与固化快照

覆盖值不单写归一化逻辑，复用全局的 `normalize_settings()`，保证两条路径永远同规则：

```python
def snapshot_join_overrides(global_settings: Mapping[str, Any]) -> dict[str, Any]:
    """以「关闭开关那一刻」的全局配置为基准生成本群固化配置（仅在配置为空时调用）。"""
    base = default_settings()
    base.update(dict(global_settings))
    normalized = normalize_settings(base)
    return {key: normalized[key] for key in JOIN_GROUP_OVERRIDABLE_KEYS}


def _normalize_overrides_patch(raw, global_settings) -> dict[str, Any]:
    """校验 + 归一化一次分群写入；非法键 → ValueError（调用方转 400）。"""
    unknown = sorted(key for key in raw if key not in JOIN_GROUP_OVERRIDABLE_KEYS)
    if unknown:
        raise ValueError("不可分群配置的键：" + ", ".join(unknown))
    base = default_settings()
    base.update(dict(global_settings))
    base.update(raw)                       # 固化值参与与全局相同的归一化
    normalized = normalize_settings(base)
    return {key: normalized[key] for key in raw}
```

收益：`join_answer_keywords` 去空、正则 strip、布尔/数值强转等规则**只有一份**；
将来全局归一化规则变化，固化配置自动跟随（防「两套类型规则分叉」）。

### 2.4 `from_dict()` 容错（旧数据 / 手改脏数据都不得炸）

| 输入形态 | 处理 |
| --- | --- |
| 无 `join_follow_global` / `join_overrides`（旧版本数据） | `True` / `{}` → **等于「跟随全局」，与现状逐键等价，零迁移** |
| `join_follow_global` 非布尔（字符串/数字/None） | 归一为 `True`（跟随全局是安全方向）+ `logger.warning` |
| `join_overrides` 非 dict（字符串/列表/None） | 置 `{}` + `logger.warning` |
| 固化表含非法键 | 逐键过滤 + `logger.warning`（防御路径；正常路径在写入时已 400 拦截） |

## 3. 开关状态机

### 3.1 生效值公式

```
effective(k) = global[k]                                   if join_follow_global
             = overrides[k]   if k ∈ join_overrides        else global[k]   （关态）
```

- 开态：全局压倒一切，`join_overrides` 只是**休眠数据**；
- 关态：固化键生效，缺失键（用户点过「恢复跟随」）回落全局。

### 3.2 转换规则

```python
async def set_group_follow_global(self, group_id: str, follow: bool) -> GroupConfig:
    """切换群级「跟随全局」开关。任何方向都不删除 join_overrides（NFR-10）。

    群必须已登记：不隐式创建记录（与 API「group_id 未登记 → 400」保持一致）。
    """
    config = self._groups.get(group_id)
    if config is None:
        raise ValueError(f"群未登记：{group_id}")
    if follow:
        config.join_follow_global = True              # 开：配置原样保留、休眠
    else:
        if not config.join_overrides:                 # 首次关闭且无配置 → 以当前全局固化（D3）
            config.join_overrides = snapshot_join_overrides(self._settings)
        config.join_follow_global = False             # 已有配置 → 直接复活，不重新生成
    self._dirty.add(KEY_GROUPS)
    await self.flush()
    if self.logger is not None:
        self.logger.info(
            "群 %s 跟随全局开关 → %s（本群固化 %d 项）",
            group_id, "开" if follow else "关", len(config.join_overrides),
        )
    return config
```

| 转换 | 行为 | 生效值变化 |
| --- | --- | --- |
| 新群登记 | 只置默认（`True`），配置为空 | 无（取全局） |
| 关（配置为空） | 以**关闭时刻**全局值固化 17 键 → 开关关 | **不变**（固化值 == 当时全局） |
| 关（配置非空） | 直接复活原配置（值可能是历史值，**不被当前全局刷新**） | 变为本群配置值 |
| 开 | 保留配置，仅门控 | 变为全局当前值 |
| 关态点「恢复跟随」 | 删除该键 | 该字段回到全局 |
| 关态编辑字段 | 写入该键 | 该字段 = 编辑值 |
| 关态 `reset:"*"` | 清空配置（显式、二次确认） | 全部字段回到全局（开关仍为关） |

- 每次转换一条 INFO 日志 + 事件总线 `audit` 类事件 `join_settings_override`；
- 「复活用的是原配置（旧值）」是 D3 的既定语义，UI 关闭 toast 必须如实说明（§9.5），
  需要以当前全局为基准重来 → 用 P1 的「以当前全局值重建」（FR-14）。

### 3.3 时序示例

```
t0 新群登记      follow=True, overrides={}           → 取全局
t1 改全局        全部跟随群生效变化                     → 新群跟随
t2 关闭开关      overrides=全局(t2值)17键, follow=False → 生效值不变
t3 改全局        自治群不变，跟随群变化                  → 分化
t4 打开开关      follow=True（overrides 原样保留）      → 自治群回到全局
t5 再次关闭      复活 overrides（= t2 的值，不是 t5 全局）→ 按需可用「重建」刷新
```

## 4. 生效值解析（唯一入口）

### 4.1 接口

```python
# src/store.py
def effective_join_settings(self, group_id: str) -> dict[str, Any]:
    """按 §3.1 公式返回完整可用配置（调用方不应修改）。"""
    base = self.settings()                       # deepcopy，已含 22 个 join_* 全局键
    config = self._groups.get(group_id)
    if config is None or getattr(config, "join_follow_global", True):
        return base                              # 开态：全局压倒一切，配置休眠
    for key, value in (getattr(config, "join_overrides", None) or {}).items():
        if key in JOIN_GROUP_OVERRIDABLE_KEYS:    # 防御：手改 KV 的脏键
            base[key] = value
        else:
            self.logger.warning("群 %s 的本群配置含非法键 %s，已忽略", group_id, key)
    return base

def join_settings_scope(self, group_id: str) -> dict[str, Any]:
    """供 WebUI：开关状态、生效值、固化键与仍跟随的键。"""
    config = self._groups.get(group_id)
    follow = bool(getattr(config, "join_follow_global", True)) if config else True
    overrides = dict(getattr(config, "join_overrides", None) or {}) if config else {}
    own = sorted(key for key in overrides if key in JOIN_GROUP_OVERRIDABLE_KEYS)
    restored = [key for key in JOIN_GROUP_OVERRIDABLE_KEYS if key not in overrides]
    return {
        "group_id": group_id,
        "follow_global": follow,
        "effective": self.effective_join_settings(group_id),
        "overrides": {key: overrides[key] for key in own},
        "own_keys": own,                          # 已固化的键（开态 = 休眠项）
        "restored_keys": restored,                # 配置中不存在的键（关态 = 仍跟随全局的字段）
        "overridable_keys": list(JOIN_GROUP_OVERRIDABLE_KEYS),
        "global_only_keys": list(JOIN_GLOBAL_ONLY_KEYS),
    }

def join_follow_stats(self) -> dict[str, dict[str, int]]:
    """影响面计数：{key: {"follow": 实际取全局的群数, "own": 实际取本群值的群数}}。"""
    stats = {key: {"follow": 0, "own": 0} for key in JOIN_GROUP_OVERRIDABLE_KEYS}
    for config in self._groups.values():
        follow = bool(getattr(config, "join_follow_global", True))
        overrides = getattr(config, "join_overrides", None) or {}
        for key in JOIN_GROUP_OVERRIDABLE_KEYS:
            takes_own = (not follow) and key in overrides
            stats[key]["own" if takes_own else "follow"] += 1
    return stats

async def update_join_overrides(
    self, group_id: str,
    patch: dict[str, Any] | None = None,
    *, clear: list[str] | None = None,
) -> GroupConfig:
    """写入固化键 / 删除固化键（恢复跟随）；非法键或非法值 → ValueError（调用方转 400）。"""
```

规则：

- **不缓存**：`settings()` 本身来自内存缓存 → 保存/切换即热生效（NFR-3）；
- **不做等值特判**：合并只看「开关 + 键存在性」，从不比较「固化值 == 全局值」（NFR-9 / AC-5）；
- `clear` 中的键不在白名单 → `ValueError`（含键名）；`clear` 不影响开关状态。

## 5. 模式（`join_review_mode`）处理（D6 + FR-12）

- 解析维持现状，**不变**，且**不受总开关管辖**：

```python
# JoinReviewer._mode_for
mode = config.join_review_mode or global_settings["join_review_mode"]
```

- 硬约束（配用例守护）：
  - `join_review_mode` **不得**出现在 `JOIN_GROUP_OVERRIDABLE_KEYS`；
  - 固化表中出现该键 → 解析时按非法键忽略并告警；
  - `POST /joins/settings` 分群路径收到该键 → 400，指引「请用『应用模式』入口」；
- **修复既有缺陷（FR-12）**：`POST /groups/join_mode` 校验放宽为
  `mode ∈ JOIN_REVIEW_MODES ∪ {""}`，`""` = 清空覆盖 = 跟随全局；错误信息同步更新；
- UI 模式下拉新增「跟随全局（当前：{全局模式}）」（value=`""`）；
- 开关文案注明「**不含审批模式**」，模式下拉紧邻总开关摆放，避免「开关开着但模式是本群的」被误读。

**全局值的编辑入口（FR-15，0.14 补齐；此前 v0.3.0 起从未实现，0.12 发布说明的声称与实现不符）**：

- 控件：**全局设置卡首个字段**「全局入群审批模式」（`JOIN_FIELD_SPECS` 中 `kind: 'select'` + `globalOnly: true`，row 0）；
- 保存：随全局形态 22 键一并提交——`GLOBAL_JOIN_SETTINGS_KEYS` 本就含 `join_review_mode`，**后端零改动**（解析、归一化、400 语义全部复用）；
- 生效链：全局值 → `_mode_for()` 的 `config.join_review_mode or 全局值` 回退 → 所有「跟随全局」的群立即生效，按群固定的群不受影响；按群下拉「跟随全局（当前：X）」随重渲染更新；
- 边界：字段标 `globalOnly` → 不进本群固化（本群卡由后端 `overridable_keys` 驱动，天然不含）、不参与影响面计数、带「全局·不分群」徽标；
- 契约：字段规格表断言改为 **== 全部 `join_*` 键**（原「减 mode」断言把历史缺口固化成了现状即需求，见实现文档坑 #17）。

### 6.1 入群审批模型按群选择（FR-11）

现状：`_llm_call(request, system, user, provider_setting="join_llm_provider_id")`
按设置项名从全局 `get_setting()` 取模型；入群调用链有 `group_id`，但没传下去。

设计：**新增关键字参数，不改动既有位置参数**（参数顺序即契约）：

```python
async def _llm_call(
    self, request, system_prompt, user_prompt, *,
    provider_setting: str = "llm_provider_id",
    provider_override: str | None = None,   # 新增：调用方按群解析好的模型 id
) -> str:
    ...
    configured = provider_override if provider_override is not None else \
        str(self.store.get_setting(provider_setting) or "")
```

调用方（`_join_judge_call`）：

```python
effective = self.store.effective_join_settings(group_id)
provider_override = str(effective.get("join_llm_provider_id") or "")
# 空串是合法值（= 跟随发言审核模型），不得折叠成 None，否则会回读全局 join_llm_provider_id；

```

- `_llm_call` 回落条件：`if not configured and provider_setting != "llm_provider_id": configured = self.store.get_setting("llm_provider_id")`（空串同样回落，且不得回读全局 join）；
- 既有直接调用点全部改关键字传参（新增参数只进关键字区）；
- 「配置了但不可用」的回退与告警日志路径**保持不变**。

## 7. API 契约

### 7.1 `POST /{plugin_name}/joins/settings`

请求体（四形态，`follow_global` 与 `patch`/`reset` **互斥**，混发 → 400）：

| 形态 | 字段 | 语义 |
| --- | --- | --- |
| 全局（现状兼容） | 22 个全局键（不含 `group_id`） | 更新全局（唯一权威来源） |
| 分群 · 开关 | `group_id` + `follow_global: true/false` | 执行 §3.2 状态机转换 |
| 分群 · 固化 | `group_id` + 若干可覆盖键（**平铺**，无 `patch` 包装字段） | 写入 `join_overrides`（编辑即固化） |
| 分群 · 恢复跟随 | `group_id` + `reset: ["k1", ...]` 或 `"*"` | 删除固化键 → 该字段回落全局；`"*"` = 清空本群配置 |

> **服务端从不按值生成或清理**：`patch` 里出现的键一律写入（哪怕与全局值相同），
> `reset` 里出现的键一律删除；开关转换只按 §3.2 规则执行（NFR-9）。
> 开态下收到 `patch`/`reset` 允许执行（写入的是休眠配置，开关状态不变），UI 不提供该路径。
> 实现上把解析与校验抽成纯函数、handler 做薄壳（可测性），语义以本节为准——见实现文档 §4.1。

错误语义（**统一显式，不再静默丢弃**）：

| 情况 | 响应 | 附加 |
| --- | --- | --- |
| 全局路径出现未知键 | 400 `未知配置键：xxx` | `logger.warning` 留痕 |
| 全局路径提交了空键集 | 400 `没有可保存的配置键` | 同上 |
| 分群路径出现不分群键（含 `join_review_mode`） | 400 `该键不支持分群配置：xxx`（模式附指引） | `logger.warning` 留痕 |
| `follow_global` 与 `patch`/`reset` 混发 | 400 `follow_global 不能与 patch/reset 同时提交` | 同上 |
| `follow_global` 非布尔（如字符串 `"false"`） | 400 `follow_global 必须是布尔值` | 同上 |
| `reset` 目标不在白名单 | 400 `不可重置非分群键：xxx` | 同上 |
| 值归一化后非法（类型/枚举越界） | 400，附键名与期望取值 | 同上 |
| `group_id` 缺失/未登记 | 400 `缺少 group_id` / 群未登记 | — |

> 兼容性评估：本插件 WebUI 是该接口唯一调用方，且已有「提交键必须已声明」的页面契约用例守护；
> 把「静默丢弃」改为 400 不破坏现有前端，反而能立刻暴露「前端拼写错误导致配置永不生效」这类缺陷。

成功响应：

```jsonc
// 全局形态
{ "settings": { "...": "..." }, "group_id": null }
// 分群形态（开关 / 固化 / 恢复跟随，均返回最新作用域便于对账）
{ "group_id": "g1", "scope": { "...": "见 7.2" } }
```

### 9.2 状态模型

```js
// 结构：「本群规则」与「全局设置」是**两张常驻卡片**（无作用域切换开关，天然并列可见）
// 未保存编辑（模块级，**按群暂存、跨渲染恢复**——实现期由「弹确认」升级而来）
state.joinEdits = { [gid]: { dirty: { [key]: 提交值 }, reset: [key] } }
// 字段作用域不维护第二份布尔状态，一律以服务端 scope 为准：
// follow_global + own_keys（固化/休眠）+ restored_keys（仍跟随）
```

- 载入：`GET /joins?group_id=` → `follow_global`、`own_keys`、`restored_keys`、`overrides`；
  字段显示值 = 开态 `settings[k]`；关态 `k ∈ own_keys ? overrides[k] : settings[k]`；
  （编辑过且未保存的字段显示暂存值；**开态渲染不采用暂存值**，防御陈旧上下文）；
- **只有用户编辑才会进 `dirty`**（属于「编辑检测」，不是生效源意图判断，不违反 NFR-9）；
- **渲染并发模型**：视图在 `clear(root)` 之后仍有网络 await，因此 `render()` 必须
  **串行互斥 + 请求合并**（单飞执行，渲染期请求合并为结束后补跑一轮）——否则交叠渲染会
  重复追加卡片、并把旧 scope 的开关盖到最新结果上（生产已复现，见实现文档坑 #18）；
  每个 mutation 之后都跟一次 `render()`，串行化后最终态必来自最新服务端数据。

### 9.3 字段渲染

| 分支 | 输入控件 | 显示值 | 徽标 / 提示 |
| --- | --- | --- | --- |
| 开态（任意字段） | **禁用** | 全局值 | 灰徽标 `全局`；若 `k ∈ own_keys` 徽标 `本群·停用`，卡级说明显示「已保留 N 项（未生效）」 |
| 关态 · 固化键 | 可编辑 | `overrides[k]` | 徽标 `本群` + 「恢复跟随」按钮 |
| 关态 · 恢复跟随键（未保存） | 可编辑 | 全局值 | 徽标 `跟随·待保存` + 「撤销恢复」按钮（已点恢复、尚未保存） |
| 关态 · 从未固化键 | 可编辑 | 全局值 | 灰徽标 `跟随`；title「修改此框即固化为本群配置」 |
| 不分群键（任意分支） | 只读 | 全局值 | 灰徽标 `全局·不分群`（字段集 = `options.join_global_only_keys`） |
| 关态 · 配置为空（清空后） | 可编辑 | 全局值 | 顶部提示条：「本群配置为空，所有字段当前跟随全局；编辑任一字段即开始固化」 |

- **零隐式状态迁移**：固化只由 ①用户编辑该字段 ②关闭开关的快照 产生；
  恢复跟随只由「恢复跟随」按钮或清空操作产生；不存在任何按值推断的状态跳变（D5）。

### 9.4 保存语义（关态）——「只提交编辑过的字段」

```js
// 关态保存：键集合来自服务端 scope，提交集合来自用户编辑（dirty）+ 显式恢复（pendingReset）
const patch = {};
for (const k of dirty) patch[k] = formValue(k);     // 编辑即固化（含把跟随字段改成新值）
const reset = [...pendingReset];                    // 本次显式恢复跟随的键
post('joins/settings', { group_id, ...patch, reset });
// 成功 → 重拉 scope 对账（以服务端为准），清空 dirty/pendingReset
```

- **绝不全量提交**：否则「恢复跟随」的字段会在下次保存时被静默重新固化（数据损坏类缺陷）；
- 开态不提供保存按钮（字段全部禁用），开关切换走独立请求（§9.5）；
- 全程没有 `formValue == settings[k]` 之类的判断，**同值固化项不会被保存逻辑误清除**；
- **未保存编辑的保护（实现期优化：按群暂存优于弹确认）**：编辑态存模块级
  `state.joinEdits[gid]`，任何重渲染（切群 / 应用模式 / 拉取 / 审批）后自动恢复，
  **不弹确认、不丢失**；仅总开关切换会清空该群暂存（服务端配置上下文已随之改变，保留旧编辑
  反而会错乱），并在 toast 明示「（未保存的字段修改已放弃）」；「放弃修改」按钮（二次确认）显式清除。

### 9.5 开关与操作（含如实文案）

| 操作 | 请求 | 提示（toast / 确认框文案） |
| --- | --- | --- |
| 开 → 关（配置为空） | `{group_id, follow_global:false}` | 「已以当前全局值生成本群配置（17 项）；此后全局变更不再影响本群」 |
| 开 → 关（配置非空） | 同上 | 「已启用本群配置（N 项）；内容为上次固化的值」 |
| 关 → 开 | `{group_id, follow_global:true}` | 「已切换为跟随全局；本群配置（N 项）已保留，可随时切回」 |
| 「恢复跟随」（单字段） | 并入下次保存的 `reset` | 徽标即时变 `跟随`，保存后生效 |
| `[保存本群配置]` | `patch + reset` | 「本群配置已保存」；失败展示 400 的具体键名 |
| `[保存全局配置]` | 全局 22 键 | 提交前提示「将影响 N 个跟随本项的群；M 群使用本群值，不受影响」 |
| `[以当前全局值重建]`（P1） | 前端把 17 键取当前全局值 → `patch` | 二次确认：「将覆盖本群现有配置（N 项）」 |
| `[清空本群配置]`（P1） | `{group_id, reset:"*"}` | 二次确认：「将永久删除本群配置（N 项），所有字段回到跟随全局」 |
| `scope` 拉取失败 | — | 错误条（含重试提示）+ **保留顶部基础卡**（群选择器/模式/拉取仍可用），本群/全局卡不渲染——失败路径不降级整页、也不静默假装开态 |

### 9.6 模式下拉（FR-12）

- 选项：`跟随全局（当前：{全局模式}）`（value=`""`）+ 四个具体模式；
- 回显：`group.join_review_mode` 为空 → 显示「跟随全局」并展示 `effective_join_mode`；
- 提交：`POST /groups/join_mode {group_id, mode}`，`mode:""` 合法；
- 摆放在总开关同一区块、标注「（不受上方开关控制）」。

## 10. 兼容、回滚与迁移

| 场景 | 行为 |
| --- | --- |
| 升级上线 | **零迁移**：缺字段 → `follow_global=True` + 空配置 = 现状逐键等价（AC-3） |
| 回退旧版本 | 旧版本 `from_dict()` 丢弃两个新字段 → **回退前需恢复 KV 备份**（发布说明必须写明） |
| 手改 KV（脏值） | §2.4 容错表：不炸、留 warning，且一律归一到「跟随全局」这个安全方向 |
| 配置导入/导出 | **该功能当前未实现**（工具页只有日志导出与数据库备份，配置导入/导出是规划项）；日后实现时必须包含两个新字段，并按 §2.4 容错校验 |
| 群记录删除后重加 | 新记录回到默认（跟随全局、空配置）——本群配置随群记录一起删除，符合直觉 |

**发布说明必须包含的三点（NFR-6）**：

1. 新增群级「**跟随全局**」开关，默认开 → **升级后行为完全不变**；关掉即本群自治
   （以关闭时的全局值为基准，此后全局变更不影响该群）；
2. 改全局只影响「跟随中的群」，自治群需单独管理；全局编辑区会显示「N 群跟随 · M 群自治」；
3. 回退旧版本需要恢复 KV 备份。

## 11. 测试计划（按风险类型，先写风险再写用例）

| 风险 | 用例 | 对应底线 |
| --- | --- | --- |
| 开关状态机错误 | 三步时序（§3.3）：关（空）→ 值不变且 17 键生成；开 → 取全局且配置保留；改全局 → 自治群不变；再关 → **复活 t2 旧值**（不被当前全局刷新） | 契约一致 |
| 新群死配置 | ① 新登记群 `follow_global=True` 且 `join_overrides == {}`（**无配置生成**）；② 改全局 → 新群生效值变化 | D1 / AC-1 |
| 升级等价 | ① `from_dict({})` → `True`/`{}` → `effective == settings`；② 源码守卫：`load()` / `ensure_group()` **不含**任何快照/迁移调用（零迁移是设计承诺） | 零迁移 / 等价基线 |
| 门控失效（休眠配置泄漏） | 构造 `follow=True` + `overrides` 有值 → `effective` 必须逐键等于全局 | 契约一致 |
| 恢复跟随 / 重新固化 | 关态 `reset[k]` → 该字段随全局变化、其余不变；再编辑该字段 → 固化并停止跟随 | FR-4 |
| 同值固化被误判（NFR-9） | ① 关闭瞬间 `overrides` 值 == 全局 → 键在 `own_keys`、改全局不跟随；② 保存后仍在 `own_keys`；③ 源码守卫：解析与保存路径不得出现按值相等生成 `reset`/剔除键的代码模式 | 意图不靠推断 |
| **保存误重新固化**（§9.4） | 页面契约 + 逻辑用例：`reset` 过的字段未被编辑时，保存 payload **不含**该键（否则恢复跟随会被冲掉） | 失败可见 / 数据安全 |
| 跨群污染 | ① A 群开关/编辑 → B 群逐键不变；② 改全局 → 只影响跟随中的群 | 共享状态谨慎 |
| 遗漏消费点（静默不生效） | 源码守卫：`src/join_review.py` / `src/profiles.py` 禁止直读判定类全局键（全局运维键走允许清单），实现后全量扫描断言为 0 | 真实契约优先 |
| 双源冲突 | `join_review_mode ∉ OVERRIDABLE`；分群 API 收到该键 400；**开关切换不改变生效模式** | 真实契约优先 |
| 白名单三向漂移 | `default_settings()` 的 `join_*` ⊆ `OVERRIDABLE ∪ GLOBAL_ONLY`；`options` 下发 == 后端元组；页面字段 ⊆ 下发集合 | 真实契约优先 |
| 影响面计数错误 | 构造 7 跟随 + 1 自治 → `join_follow_stats` 与逐群实际开关状态一致（含"开态但有休眠配置"的群仍计 follow） | 失败可见 |
| 错误被吞 | 八类非法输入（解析层六类：未知键 / 分群控制键缺 group_id / 全局空键集 / 混发 / 非布尔 / 非法 reset；后置两类：值归一化非法 / 群未登记）各自 400 且 message 含键名；防御路径断言产生 warning | 失败可见 |
| 归一化分叉 | 同一非法值在全局路径与 `patch` 路径归一化结果一致；关闭快照值 == 全局归一化值 | 真实契约优先 |
| 旧数据兼容 | `from_dict` 四种脏形态（§2.4）均不抛异常且归一到安全方向 | 旧数据缺省兜底 |
| 绕过状态机写配置 | 经通用 `update_group()` 提交 `join_follow_global` / `join_overrides` → 被拒绝（防御），只能走专用方法 | 失败可见 |
| 未保存编辑丢失/错乱提交 | 页面契约：源码含按群暂存结构（`joinEdits`）与就地反馈（`discardBtnNode`/`本群·待保存`）；保存 payload 只含 `dirty`+`reset`；总开关切换清空暂存并在 toast 明示 | 真实契约优先 |
| 等价基线 | 默认态（开 + 空配置）下，既有入群判定用例（门槛/答案/头像/阈值/拉黑）**复用不改断言**直接通过；「先建群后改全局」类用例在本模型下**应当通过**（语义未变） | 等价基线 |

| 模式选项（FR-12） | `groups/join_mode` 提交 `""` 成功且 `effective_join_mode` 回落全局；非法值 400；UI 下拉含「跟随全局」 | 真实契约优先 |
| 模型按群（FR-11） | 关态固化模型 → 调用点收到该模型；开态/恢复跟随 → 走全局回落链；模型不可用 → 既有回退告警仍触发 | 真实契约优先 |

| fake 比真实类更全 | fake store 必须实现 `effective_join_settings` / `join_settings_scope` / `join_follow_stats` / `update_join_overrides` / `set_group_follow_global`，并断言 fake 无真实类没有的方法 | 测试替身诚实性 |

## 13. 风险与取舍

| 编号 | 风险 | 影响 | 对策 |
| --- | --- | --- | --- |
| R1 | 遗漏某个消费点 → 分群配置静默不生效 | 用户以为配置了其实没有 | 解析唯一入口 + 源码守卫用例 + 消费点清单（§6）随实现核对 |
| R2 | **复活旧值的时点困惑**：关→开→再关拿到的是上次固化的旧值，不是当前全局 | 用户以为"关闭=拿最新全局" | 关闭 toast 按「生成 / 复活」分支如实提示（§9.5）+ P1「以当前全局值重建」（FR-14） |
| R3 | 开态下用户误以为「已保留的本群配置」正在生效 | 误判判定依据 | 字段禁用 + 灰徽标 + 「已保留 N 项（未生效）」文案 + 留痕三态 |
| R4 | 「开关开着但模式是本群的」混合态被误读 | 配置误解 | 开关标题注明「不含审批模式」、模式下拉紧邻摆放并标注独立（§5/§9.6） |
| R5 | 把静默丢弃改 400 影响未知调用方 | 兼容性 | 已确认 WebUI 是唯一调用方，契约用例守护；发布说明标注 |
| R6 | 恢复跟随的字段被下次保存静默重新固化 | 数据安全 | **只提交 dirty 字段**（§9.4）+ 专门用例 + 页面契约守卫 |
| R7 | 同值固化项在「生效值」上与跟随不可区分 | 误判依据 | 开关状态 + 字段徽标 + 留痕三态（全部按作用域而非值表达） |
| R8 | 误把全局设置当成当前群配置 | 改错对象 | 两张卡标题自证：「本群规则（当前群：{群名}）」vs「全局设置（新群与跟随群生效）」；按钮文案「保存本群配置」vs「保存全局配置」；全局卡每项标注影响面 |
| R9 | v1.0「默认独立」模型的历史教训（建群复制全局值曾被回退） | — | **本版设计已规避**：默认跟随、不预生成配置、`mode` 明确排除（D1/D6），此风险仅作背景记录 |
| R10 | 固化表每群 17 键 × N 群 | 体积可忽略（KV JSON 数百字节/群） | 记录备查，不做分页/压缩 |
