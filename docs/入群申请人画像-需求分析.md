# 入群申请人画像增强与反「发片机器人」自动审批 · 需求分析

> 版本：v0.1（待评审）　|　日期：2026-09-26　|　关联：`docs/设计方案.md`、`docs/平台能力调研.md`
> 事实依据：腾讯 QQ 机器人官方文档 api-v2「群聊管理」、AstrBot v4 文档与源码、NapCat 协议端实现（本机 `napcat.mjs`）

---

## 1. 背景与问题

插件（`astrbot_plugin_qq_group_manager`）已实现入群自动审批，但**判定依据过少**：

- 官方通道 `JoinRequest` 只有：`member_openid / username / union_openid / apply_source / invited_by / bot / risk_tips / verify_info`。
- OneBot 通道的加群请求事件只有：`flag / group_id / user_id / sub_type / comment`，**没有昵称**。
- 现状代码 `src/platforms/onebot.py feed_request()` 读 `raw.get("username")` → 该字段在 OneBot 请求事件里不存在，**昵称恒为空**（现存缺陷）。

结果是：判定只能靠「昵称文本 + 验证消息 + 平台风险提示 + 是否机器人」。
而广告/发片机器人的典型特征是**账号维度**的：注册时间极短、QQ 等级极低、无 QID、资料空白、头像擦边或含引流二维码——这些信号当前**一个都拿不到**。

---

## 2. 调研结论：数据源能力矩阵（事实）

| 需要的信息 | QQ 官方（qq_official） | OneBot v11（aiocqhttp / NapCat） | 依据 |
| --- | --- | --- | --- |
| 账号标识 | ❌ 仅 `member_openid`（不透明，禁止反查） | ✅ `user_id` = 真实 QQ 号 | 官方 JoinRequest；OneBot 请求事件 |
| 昵称 | ✅ `username` | ⚠️ 事件里没有，需 `get_stranger_info` | 同上 |
| 头像 | ❌ JoinRequest 无 avatar 字段 | ⚠️ 无字段，可用 QQ 号拼 `q1.qlogo.cn` | JoinRequest 结构；NapCat 用同一 CDN |
| 账号等级 | ❌ 无此字段/接口 | ✅ `get_stranger_info.qqLevel` | NapCat 源码实证 |
| 注册时间 / 账号年龄 | ❌ 无 | ✅ `get_stranger_info.reg_time` | NapCat 源码实证 |
| QID / 性别 / 年龄 / VIP | ❌ 无 | ✅ `qid / sex / age / is_vip / vip_level` | NapCat 源码实证 |
| 是否机器人 | ✅ `bot` | ✅ `get_group_member_info.is_robot`（入群后） | 官方文档；NapCat 源码 |
| 平台风险提示 | ✅ `risk_tips`（warning_tips / top_tips） | ❌ 无 | 官方文档 |
| 验证方式/问答 | ✅ `verify_info` | ⚠️ 仅 `comment` | 官方文档；OneBot 事件 |

> 注：`qqLevel`/`reg_time` 是 **NapCat 扩展字段**，非 OneBot v11 标准；换协议端（Lagrange 等）可能缺失，必须按「可能拿不到」设计。
> 注：官方文档中 `User` 模型虽定义 `avatar`，但 `/users/@me` 返回的是**机器人自己**；入群申请对象不含头像，也无「按 openid 查任意用户资料」的接口。

## 3. 用户故事

| 编号 | 角色 | 故事 | 期望 |
| --- | --- | --- | --- |
| US-1 | 群主 | 一个注册不到 3 天的 QQ 申请入群 | 自动拒绝（可配）+ 拉黑，并留痕理由 |
| US-2 | 群主 | 申请人昵称正常，但头像是擦边图/引流二维码 | 头像送多模态复核 → 自动拒绝 |
| US-3 | 管理员 | 处理待审申请 | 待审列表直接看到头像缩略图、QQ 等级、账号年龄，不必逐个点开 |
| US-4 | 群主 | 协议端不支持画像（标准 OneBot / 官方通道） | 不误杀：按策略转人工，并在界面说明「本通道拿不到画像」 |
| US-5 | 管理员 | 同一个发片号在多个群反复申请 | 画像可跨群复用；被拒次数达阈值进入跨群黑名单候选 |

## 4. 功能需求

### P0（首版必须）
- **FR-1 画像采集（OneBot）**：处理加群请求时用 `user_id` 调 `get_stranger_info`，落成统一画像结构；失败降级为空画像，不抛异常。
- **FR-2 头像 URL 构造**：由 QQ 号生成头像直链（`q1.qlogo.cn`），无需额外接口。
- **FR-3 硬规则门槛**：账号年龄、QQ 等级、QID 三项阈值，可单独开关/设 action（拒绝 / 转人工 / 放行）。
- **FR-4 资料缺失策略**：画像不可得（协议端不支持 / 调用失败 / 官方通道）时的统一策略：`pass | manual | decline`（默认 `manual`）。
- **FR-5 LLM 提示词增强**：把画像（等级、账号年龄、注册时间、性别、QID、资料是否缺失、头像 URL）注入判定 prompt，并明确「资料缺失 ≠ 可疑」。
- **FR-6 审计与展示**：画像随申请落库；WebUI 待审/历史表、`入群申请` 指令文案、通知文案展示等级与账号年龄。
- **FR-7 能力探测与降级**：新增能力项「申请人画像」，OneBot 可探测、官方标记为不支持；任何不可用都写能力台账并降级。
- **FR-8 缓存与限频**：画像按 `(平台实例, QQ号)` 缓存（默认 7 天）；单次申请最多 1 次远端调用；失败计数触发熔断，熔断期内直接走「资料缺失策略」。

### P0-2（首版一并交付，已确认）
- **FR-9 头像多模态审核**：开关 `off | approve_only | always`；把头像 URL 作为 `image_urls` 追加给 LLM，识别擦边/引流二维码；模型或图片不可用时静默降级为纯文本判定。

### P2（下一版，登记跟踪）
- **FR-10 跨群画像共享与联动**：同一 QQ 号在多群被拒达阈值 → 生成跨群黑名单候选，管理台一键确认。
- 入群后补充画像（成员列表/详情，内邀能力）反哺画像库。

## 5. 非功能需求

| 维度 | 要求 |
| --- | --- |
| 兼容 | 官方通道行为**零变更**；不因新增逻辑产生额外接口调用（避免 11253/11282 噪音） |
| 降级 | 任何画像失败都不得阻塞或改变审批主流程；默认 fail-open（转人工） |
| 性能 | 单条申请 ≤ 1 次远端画像调用；缓存命中为 0 次；不引入阻塞式网络等待串行化多群 |
| 限频 | 画像调用独立限速（默认 30 QPM/实例）+ 并发上限，避免协议端风控 |
| 隐私合规 | 仅存审核必需字段；管理台可显完整 QQ 号与头像，群内指令/通知一律脱敏；不落聊天正文 |
| 可配置 | 所有新增阈值默认**关闭**（0/off），安装即与现行为一致 |
| 可测试 | 画像解析、硬规则、缺失策略、迁移均可用 Fake 单测覆盖，无需真机 |

---

## 6. 明确不做（Non-goals）

1. 不尝试 openid → QQ 号反查（官方明确 ID 与真实 ID 无关、无接口）。
2. 不为官方通道「造」头像或等级（接口不存在）。
3. 不引入第三方依赖（保持纯标准库）。
4. 不因画像风险自动**踢出已在群成员**（本需求只作用于入群申请）。

## 7. 验收标准

| 编号 | 验收 |
| --- | --- |
| AC-1 | OneBot 收到加群请求后，画像含 QQ 号、昵称、QQ 等级、账号年龄、头像 URL；昵称不再为空 |
| AC-2 | 协议端不返回等级/注册时间时，申请不会报错，按「资料缺失策略」处理 |
| AC-3 | 开启「账号年龄 < N 天拒绝」后，命中者自动拒绝并拉黑（可配），审计可查理由 |
| AC-4 | 官方通道收到申请，全程不产生画像相关请求，审批行为与升级前一致 |
| AC-5 | 待审列表显示头像、QQ 等级、账号年龄；无画像时显示「本通道不支持」而非空白 |
| AC-6 | 数据库旧库升级后自动补齐画像列，历史记录可正常读取 |
| AC-7 | 头像多模态开启时，头像 URL 随 prompt 送审；模型不支持图片时自动降级且不报错 |
| AC-8 | ruff 通过，新增单测通过，`入群申请` 指令与通知文案展示新字段 |

## 8. 已确认决策（v1.0 定稿）

| 决策点 | 结论 | 影响 |
| --- | --- | --- |
| 首版范围 | **P0 全做 + 头像多模态（FR-9）一并交付** | 设计需同步解决 `judge_call` 图片通道与 LLM 限频接入 |
| 资料缺失策略 | **默认 `manual`（转人工）** | 官方通道/标准协议端不会误杀，代价是人工量上升 |
| 硬门槛默认值 | **全关**（`join_min_account_days=0`、`join_min_qq_level=0`、`join_require_qid=false`） | 升级即零行为变更；先跑一周数据再收紧 |
| QQ 号/头像展示 | **管理台完整显示；群内指令与通知一律脱敏** | 展示层按此实现，群内文案沿用 `mask_openid` |
| 跨群联动 FR-10 | **下一版再做** | 本期只做单群判定与画像库，预留接口 |
| 画像缓存/留存 | 随 `retention_join_days`（默认 90 天）一并清理 | 无需新增清理任务 |
