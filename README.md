# QQ 群管理 · AstrBot 插件

> 给 **QQ 群**（QQ 官方机器人 `qq_official` / `qq_official_webhook`，或非官方 OneBot v11 `aiocqhttp`）补上群管理能力：**内容审核、入群审批、成员管理**，以及一个能真正干活的管理台。

```text
QQ 群消息 ──► 本地规则（形近字/黑话/模板，零成本）
                 ├── 精确命中硬规则 ──► 立即处置（撤回 / 禁言 …）
                 └── 命中变体或风险分 ≥ 阈值 ──► LLM 判定 ──► 按类别与严重度处置
                                                        └──► SQLite 审计 + 管理台可视化
```

- **版本**：0.11.1 ｜ **平台**：`qq_official` / `qq_official_webhook`（QQ 官方）+ `aiocqhttp`（OneBot v11）｜ **许可**：MIT
- **零第三方依赖**：只用标准库 `sqlite3` + AstrBot 官方 SDK（`pypinyin` 为可选增强）

---

## 为什么需要它

QQ 机器人（官方 OpenAPI，或 OneBot v11 协议端）提供了群管理与消息能力，却没有配套的运营工具：谁在发广告、要不要撤回、该不该禁言、入群申请怎么批量审 —— 全靠人工。这个插件把这些串成一条自动流水线，并且**每一步判定与处置都可回溯**。

## 功能

### 🛡️ 内容审核
- **两级判定**：本地规则先过滤（零 token 成本），命中变体或风险分达阈值才交给 LLM；闲聊不消耗任何模型调用。
- **先推理后结论**：送审时附带最近 N 条群消息作为语境（`llm_context_messages`，0 = 关闭），模型先写 `analysis`（判断过程）与 `evidence`（逐字引用原文），再给 `verdict / category / severity / confidence / reason / suggested_action`；解析失败或置信度不足一律降级为"需人工复核"，**不误伤**。
- **处置矩阵**：1–5 级严重度对应警告 / 撤回 / 禁言 / 拉黑 / 移出，可用模式（严格 / 标准 / 宽松 / 仅记录）整体调节。
- **dry-run 演练**：撤回、禁言等破坏性动作只写审计不执行（警告照常发送），确认判定质量后再上线。
- **可选图片送审**：图片以多模态交给同一个审核模型（不送 / 仅图文混排 / 纯图也送）。

### 🧬 变体识别
广告号不会老实写"加群领资料"。插件为每条消息生成多个归一化视图，**形近字、拆字、繁体、插符号、空格、全角、拼音**都能还原：

| 原始写法 | 还原结果 |
| --- | --- |
| `珈裙苓资料123456` | 加群领资料123456 |
| `加 群 领 资 料` / `加-群-领-资-料` | 加群领资料 |
| `看爿+ 姿源+ 浮力+` | 看片 资源 福利 |
| `加君羊 领资料`（拆字） | 加群 领资料 |
| `老司機發車`（繁体） | 老司机发车 |
| `jiaqun ling ziliao`（拼音） | 加群领资料 |

配套 **15 条广告模板**（拉群引流 / 开群福利引流 / 黑话引流 / 深夜福利 / 盗版资源 / 召唤式引流 / 私聊引流 / 兼职刷单 / 赌博引流 / 涉黄引流 / 涉黄黑话 / 药品 / 荐股杀猪 / 贷款 …）、**168 条形近字表**、**12 条拉丁拼音别名**（jia→加、qun→群、kouqun→扣群）、**41 个引导动作词**、**45 个诱饵资源词**与 **45 条黑话标记词**，用"动作词 × 诱饵词"的组合识别结构，而不是依赖单个关键词；命中只代表"值得送审"，是否违规仍由 LLM 判定。

### ⚖️ 申诉闭环
- 成员**回复被处置的消息**发送 `申诉 <理由>`，插件用 Reply 精确定位原审核事件（取不到才回退"最近一条"）。
- 群管回复申诉消息发送 `申诉通过 / 申诉驳回 [理由]`，或在管理台「申诉」视图处理；**通过时自动解禁**（若原事件产生过禁言）并追加 `appeal_accepted` 动作留痕，**不删除、不改写原审核事件**。
- 可选**误判自学习白名单**（`appeal_auto_whitelist`，默认关）：申诉通过后把原消息摘要写入白名单，后续同内容消息**跳过 LLM 送审**但仍写审计（`verdict=allow / category=whitelisted`），可随时在管理台撤销。

### 🧭 竞赛域名白名单
- 内置 `codeforces.com / atcoder.jp / luogu.com.cn / ac.nowcoder.com …` 等竞赛域名，白名单内的链接**不计 link 分（25 分）**，但仍走完整规则、审计与 LLM 送审判断 —— **只降权，不豁免**。
- 按点边界后缀匹配：`m1.codeforces.com` 命中 `codeforces.com`，`fake-codeforces.com` 不命中；白名单为空或开关关闭时行为与旧版完全一致。

### 🚪 入群审批
- 按群轮询入群申请（游标 + 幂等去重，重启不重复审批）。
- 判定链：黑名单 → 机器人账号 → 平台风险提示 → 信任邀请人 → LLM 判定，输出通过/拒绝与理由。
- 四种模式：`off / strict / standard / human`（高置信自动、低置信转人工、或全部人工）。

### 👥 成员与群务
- 手动禁言 / 解禁（指令与管理台双入口），本地禁言台账每 5 分钟与平台对账。
- 黑名单双轨（平台接口不可用时自动落本地）、成员查询、批量移除（二次确认）。
- 平台**入群自动审批策略**透明化：查看 / 启停官方策略、触发扫描、白名单管理，并检测与插件审批的冲突。

### 📊 审计与管理台
- SQLite 审计库：审核事件、动作执行、入群申请、API 调用、能力受限、禁言台账、日统计、**申诉白名单**。
- 管理台 10 个视图：总览 / 群管理 / 日志中心 / 工具 / 策略 / 关键词 / **规则增强** / 成员与禁言 / 入群审批 / **申诉**。
- 「规则增强」自带**判定测试**：粘贴一段文本即可看到是否送审、风险分构成、归一化视图与命中依据（不发消息、不花 token）。

## 安装

1. AstrBot 已启用 **QQ 官方机器人**（`qq_official` / `qq_official_webhook`）或 **OneBot v11**（`aiocqhttp`）适配器之一，并能正常收发消息。
2. 在 AstrBot 插件页填入仓库地址安装，或手动放入插件目录：

```text
https://github.com/td1336065617/astrbot_plugin_qq_group_manager
```

3. 重载插件，打开 **插件管理 → QQ群管理 → 管理台**。

**首次配置（建议 4 步）**

| 步骤 | 操作 |
| --- | --- |
| 1 | 在群里发一条消息，让插件登记这个群（平台没有"机器人在哪些群"的接口，只能靠消息发现） |
| 2 | 「群管理」页点**能力自检**，确认机器人是群管理员、且群已开启**接收全部消息** |
| 3 | 点**启用审核**（会先做一次能力探测；未开启接收全部消息会被拒绝并给出手机 QQ 操作指引） |
| 4 | 保持 **dry-run** 观察几天，确认判定质量后再关闭，并按需把模式切到「标准」 |

## 权限与平台限制（必读）

QQ 官方群管理接口分三档（下表为 **QQ 官方通道**；OneBot 通道通过 call_action 调用协议端接口，能力差异见「支持平台」一节），插件会**逐项探测并把受限原因写进审计与日志**，不会假装成功：

| 能力档位 | 包含接口 | 典型现象 |
| --- | --- | --- |
| 仅白名单可用 | 群信息、机器人群内状态、成员列表、黑名单、批量移除 | `err_code 11253`（该接口仅白名单机器人可用） |
| 白名单 + 内邀 | 成员管理 5 个接口（平台正在内邀接入） | 同上 |
| 需群管理员 | 入群申请列表 / 审批、禁言读写 | 机器人不是群管理员时无权限 |

两条硬约束：

- **平台默认只推送 @机器人 的消息**。要审核全部消息，需由群管理员在手机 QQ 中开启「接收全部消息」，否则插件收不到消息（平台行为，不是插件缺陷）。
- **撤回仅限消息发出后 2 分钟内**，且机器人必须是群管理员。

## 指令

指令为**全匹配**，可带 `/` 前缀（例如 `/群信息`）。群开启「接收全部消息」后，非 @ 场景也能使用。

**所有人可用**

| 指令 | 说明 |
| --- | --- |
| `群管理菜单` | 显示菜单 |
| `群信息` | 本群档案与机器人群内状态 |
| `审核状态` | 审核开关、生效模式（含来源）、我的豁免状态 |
| `申诉 <理由>` | 对被处置的消息提出申诉（回复该消息后发送，精确定位原事件） |

**群主 / 群管理员**

`审核开启` · `审核关闭` · `审核模式 严格/标准/宽松/仅记录/跟随` · `审核阈值 0.0-1.0` · `dry-run 开启/关闭` ·
`关键词 列表/添加/删除` · `信任 / 取消信任 @某人` · `禁言 @某人 10分钟` · `解禁 @某人` · `撤回` ·
`审核日志 5` · `审核统计 今日` · `申诉通过 / 申诉驳回 [理由]`（回复申诉消息） · `入群审核 开启/关闭/模式` · `入群申请 / 入群通过 / 入群拒绝` ·
`黑名单 列表/添加/移除`

**AstrBot 管理员**

`群管理自检`（逐项探测平台能力并给出建议） · `群管理配置` · `全局拉黑 @某人 <理由>` / `全局解除 @某人` / `全局拉黑`（跨群黑名单，命中后任意群的入群申请都会被拒绝）

## 配置

常用项（完整说明见 [docs/CONFIG.md](docs/CONFIG.md)）：

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `dry_run` | 开 | 只记录 + 警告，不执行撤回 / 禁言 |
| `mode` | lenient | 处置强度：strict / standard / lenient / log_only |
| `send_conditions` | rule_hit + risk>=60 | 送审条件，风险分阈值可调 |
| `image_review` | off | 图片是否送审（off / with_text / always） |
| `llm_provider_id` | 空 | 审核使用的模型；留空跟随会话默认模型 |
| `auto_enforce_normalized` | 关 | 变体命中是否直接处置（默认只送审，由 LLM 判定） |
| `domain_allowlist_enabled` | 开 | 竞赛域名白名单降权（白名单内链接不计 link 分，仍送审） |
| `domain_allowlist` | 内置竞赛域名 | 白名单域名列表（按点边界后缀匹配） |
| `appeal_enabled` | 开 | 是否接受成员申诉 |
| `appeal_auto_whitelist` | 关 | 申诉通过是否自动加入误判白名单（跳过 LLM 送审，仍写审计） |
| `appeal_notify` | 开 | 申诉处理结果是否回执申诉人 |

## 常见问题

**群里发消息没有任何反应？**
先确认机器人能收到这条消息：群未开启「接收全部消息」时，只有 @机器人 才会被推送。其次确认该群已**启用审核**（管理台「群管理」或群内 `审核状态`）。最后查插件日志里的 `收到指令 / 规则评估` 行 —— 现在每一步都会留痕。

**判定违规了，为什么没撤回 / 没禁言？**
三层保护依次检查：① 群级模式是否被覆盖为 `lenient`（`审核状态` 会标注"群级覆盖 / 跟随全局"）；② `dry_run` 是否还开着；③ 机器人是否群管理员（非管理员时撤回与禁言会被跳过并记录原因）。日志会直接写出"以下动作未执行：[…]（模式=…，dry_run=…）"。

**闲聊会不会被送去烧 token？**
不会。默认送审条件是"规则 / 模板命中"或"风险分 ≥ 60"，纯闲聊与普通链接（25 分）都不送审。

**会不会误伤正常发言？**
变体与模板命中**只送审**，是否违规由 LLM 判定，且要求严格 JSON + 置信度门槛，解析失败一律不处置。开发环境自带真实反垃圾语料回归（65 条正样本 / 38 条负样本），保证"该拦的拦住、正常聊天不误报"。

**数据存在哪？**
`AstrBot/data/plugin_data/astrbot_plugin_qq_group_manager/moderation.db`（SQLite + WAL）。消息正文默认不落库，可由配置 `store_text` 开启；保留期、导出、备份、清空都在管理台「工具」页。

## 开发

- 运行时依赖 AstrBot（`astrbot`、`botpy`），插件本身**不引入第三方库**。
- 结构：`main.py`（入口与指令）+ `src/`（api_client / rules / normalize / moderator / actions / audit / store / web_api …）+ `pages/manage/`（管理台 SPA）。
- 仓库只发布插件本体；测试套件与设计文档保留在开发环境，发版前会跑全量回归。
- 扩充判定能力**无需改代码**：管理台「规则增强」维护广告模板与形近字表，「关键词」维护硬 / 软规则，保存即生效。

## 支持平台（QQ 双通道）

- **QQ 官方**：qq_official（WebSocket）/ qq_official_webhook（Webhook），复用 botpy 通道；群信息、禁言、撤回、入群审批等能力受白名单/内邀/群管理员限制。
- **QQ 非官方**：aiocqhttp（OneBot v11，如 NapCat / Lagrange / go-cqhttp）；群管理通过 call_action 调用协议端接口。
- 能力差异（如 OneBot 无原生黑名单、入群审批走 request 事件）会显式降级并留痕，不会崩溃或刷屏。
- 平台判定与通道抽象位于 src/platforms/，官方族行为与改造前保持一致。
